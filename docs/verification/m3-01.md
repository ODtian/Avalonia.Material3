## 场景清单

- 加载主题和按钮，显示真实内容，点击产生宿主反馈。
- Light → Dark → Light 更新同一个按钮的语义配色与渲染帧。
- Tab 可见焦点；Space 按下反馈、释放激活；Enter 命令和参数传递。
- 悬停、按下与禁用的渲染结果不同；禁用不激活且不获得 Tab 焦点。
- 宿主运行时更换颜色、字体、尺度、圆角和减少动效输入。
- ContentTemplate 中的中英文混排内容获得布局；命令使用公开参数。
- 48 DIP 触达区域的非视觉部分接受触摸；拖出后释放取消。
- Automation peer 暴露名称、Button 角色、启用状态；非法字体尺度拒绝替换已有主题。
- 相同测试在源码库入口与真正的 NuGet 包入口执行；两份实际 sample 的动作、主题与绑定结果一致。

## TDD 与审查

基础点击样式、Dark 配色、可见键盘焦点、悬停/按下、禁用、初始令牌输入、包宿主场景均先观察失败，再完成相应纵向实现。其他继承自 Avalonia 的行为通过公开宿主场景回归，不另写内部 mock。

审查固定点为起始 `main` 提交 `da314a4`（`git diff da314a4...HEAD`），沿 Standards 与 Spec 两轴执行；依照母规格的主代理直接推进约定，不声称启动子代理。

### Standards

发现 1 项判断型问题（无额外编码规范硬违反）：`Host_loads_a_filled_button_and_receives_pointer_feedback` 重复构造、关闭宿主（possible Duplicated Code）。已统一到 ButtonHost，并保证主题安装早于窗口初始化、结束时撤销测试主题。两个独立 sample 的入口和简单交互代码刻意独立，避免消费示例依赖共享源码项目。

### Spec

发现并修复 3 项：

1. “验证键盘焦点”：原模板 `Margin="0,4"` 让焦点环与左右容器重叠；改为四边留出 3 DIP 环 + 2 DIP 间距，按下时环同步变形，新增公开渲染像素回归。
2. “初始字体契约”：有限但极大的 Scale 会生成无限字号；主题现在拒绝溢出的输入，新增 `double.MaxValue` 回归。
3. “宿主启动与基础主题验证”：首帧桌面截图可能被前台应用遮挡；截图前先通过 UI Automation 确认宿主焦点，再重新生成并人工检查明暗截图。

结论：Standards 1 项、Spec 3 项均已处理；无未解决发现。最大风险分别是重复测试构造（Standards，判断型）和焦点环重叠（Spec，已修复）。
