## Criteria and explicit limits

All ticket form/activity/outcome/pause/reduced-motion/control-time/automation-description/demo/package paths are implemented and exercised. The library has no application task scheduler, retry queue, service or cancellation ownership. #19 can consume the loading/progress controls by driving their public value/status properties. #20 must wire `ProgressFeedbackPage` into aggregate navigation and finish release/platform work.

No claim of human Narrator/NVDA reading, Android, physical touch hardware, non-Windows native platforms, AOT/trimming, final API stability or public package publication is made. Native rejected SetValue is checked as rejection/no mutation, not a precise COM HRESULT mapping. Numeric progress does not guarantee a spoken live announcement; the host decides the announcement policy.

**Normative projection limitation:** wave paths are sampled sine/radial waves; rounded loading silhouettes use angular correspondence rather than AndroidX feature-matching Morph/PathMeasure; motion consumes the complete #3 theme inputs, including SlowSpatial for loading. Exact Compose frame/pixel/velocity equality (including its local0.6/200 loading spring) has neither been implemented nor certified. This is explicit, not hidden by calling property-only controls or screenshots formal conformance.
