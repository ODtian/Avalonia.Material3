# M3-07 / Issue #6 — verification and limitations

## Delivered seam

`MaterialTheme` + public `MaterialTextField` in an actual Window, and the public packaged `Gallery.Pages.TextFieldsPage`. Tests observe edited values, native caret/selection/undo, focus, visible text/layout, rendered state feedback and public automation providers. They do not reach into the control's private state or depend on private visual names. The replacement-template scenario uses **documented native TextBox template parts**, not undocumented internals. No editor collaborators are mocked.

[Public contract and examples](../components/m3-07.md). Normative references: locked Material component entry and AndroidX `11ece46a49d485c7644e53cb0684a611d7a0ec10`, FilledTextFieldTokens v0_210 / OutlinedTextFieldTokens v0_103. Geometry, role/default colors and state alpha vectors are independent literals/worked examples from that baseline. This is not a claim of upstream pixel-identical normative certification.

## Repeatable manual protocol / not verified

1. Run the fresh sandbox TextFieldHost with NVDA or Narrator. Traverse by Tab/Shift+Tab: validate action, editable fields, clear/reveal actions, read-only value, next field; disabled fields must be skipped. Confirm Edit role/name, read-only status, clear/reveal names and usable focus indication.
2. Submit an empty form. Confirm the first invalid editor receives focus; error text is accessible and not only a color. Type and correct an email. Confirm label/value stay consistent, helper is restored, and the reader's actual announcement policy is usable. Record reader/version/platform and spoken output; automation HelpText alone does not certify announcements.
3. Activate a real Chinese IME. Compose `中文 Atlas`, move/cancel candidates, commit, select/replace text, move the caret and undo; observe native candidate position and counter changes only for committed text. Repeat in multiline and password forms with the platform's sensitive-input behavior. Do not substitute direct Text assignment for this step.
4. Toggle light/dark, use 200% text and resize to 320 DIP. Scroll the whole page; confirm helper/error text and editable values remain readable, slot targets reachable, and outlined labels do not overlap or sit above the notch. Test actual host font fallback and any licensed/custom fonts.
5. Repeat pointer/touch, clipboard, soft-keyboard/candidate positioning and platform selection affordances on the target mobile platform. These are **not Android runtime verification** in this ticket.

**Unverified/unmet evidence boundaries:** actual screen-reader spoken announcements; a completed real Chinese IME candidate session; real mobile/Android touch-selection/soft-keyboard behavior; platform protected-edit/IsPassword flag; AOT/trimming/stable API baseline. The public peer intentionally prevents password value/event disclosure, but Avalonia's peer API does not expose an IsPassword override here. #20 owns aggregate gallery wiring and final release/platform verification. No criterion above is silently presented as manually/platform verified.
