### Native red found a real accessibility defect

The first desktop attempts passed initial dialog role, disabled/filtering policy, validation, editor focus and keyboard containment, but failed after closing when **UIA FocusedElement returned COM E_FAIL** despite a visible entry focus ring. Flattening dialog peers into host.Children was incompatible with Avalonia ControlAutomationPeer's automatic reconnection to visual parents. Eager invalidation alone also produced native navigation E_FAIL.

Fix: public **MaterialOverlayContentPresenter** and per-layer scopes preserve the visual/automation parent graph, hide disabled modal-background descendants rather than flattening children, and eagerly reconnect cached children before focus notifications. A fresh package/native run then passed; the final integrated run passed again. This was not papered over by replacing native focus assertions with property-only checks.

An initial SendKeys string with a space hit the active Windows Chinese IME: Space accepted a candidate, leaving a following Latin word in preedit and ValuePattern incomplete. The final native test uses one Latin word plus Enter to commit current native preedit, asserts the dialog did not submit, and observes the edited value before focused-action Enter confirmation. No keyboard-layout, private configuration or security setting was changed. This observation does not constitute comprehensive IME validation.
