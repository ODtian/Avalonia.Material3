## Explicit boundaries / #20

No pinned group, segmented selection mode, split recipe or split size is omitted. Functional control, host/public consumption, layout/input/automation, theme/motion and package evidence are delivered. This does **not** assert exhaustive normative, native-pixel or human accessibility conformance.

- Human Narrator/NVDA reading, physical touch hardware, Android/other native platforms, AOT/trimming, final published release/API stability and real App M11 were not run/claimed.
- Analytical spring retargeting/limits, immediate segmented indicator replacement, effective alpha/chevron projection and vertical focus-envelope spacing are not exact Compose velocity/frame/indicator-motion parity.
- Multiline corner caps and narrow horizontal EffectivePadding are explicit adaptations; default nominal-size pin vectors remain tested. Below physically feasible target/content width, hosts must provide a layout alternative. Arbitrarily oversized interactive content and host clipping/custom templates remain host responsibilities.
- Complex Control overflow content uses an accessible textual name/fallback instead of duplicating a control parent. This is a compact overflow action/option surface, not #15's complete rich menu/submenu API.
- Split host owns contextual menu/content and synchronizing optional Flyout Opened/Closed with IsExpanded; the gallery demonstrates actual destination options. Keyboard Escape return from sibling context is implemented by the host page, not magic library traversal.
- #20 must wire `ButtonGroupsPage(MaterialTheme)` into aggregate navigation, consolidate verifier/scenario links and final public API/release/platform evidence. Package-host demonstration already runs independently.
