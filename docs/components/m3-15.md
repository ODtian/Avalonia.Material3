# M3-15 — Navigation bar, rail and tabs with real content

Issue #14. Namespace **`Avalonia.Material3.Controls`**, Avalonia 12.1.3 / net10.0. Install `MaterialTheme` before creating controls. This extends the [preview contract](../public-contract.md), consumes [M3-02 semantic tokens](m3-02.md) and reuses Avalonia Button input/command foundations from [M3-03](m3-03.md). There is no routing, URI resolution, product state, page service or business dependency in the library.

## Controls and presentation

| Control | Default | Supported presentation |
| --- | --- | --- |
| `MaterialNavigationBar : MaterialNavigation` | Vertical item layout | Bottom bar, horizontally distributed items; `ItemLayout = Vertical / Horizontal` means icon above / beside label, **not** the direction of the bar |
| `MaterialNavigationRail : MaterialNavigation` | Collapsed, 96 DIP, vertical items | Non-modal left rail, `IsExpanded`, both item layouts in both expansion states, optional 80-DIP narrow collapsed width |
| `MaterialTabs : MaterialNavigation` | Primary, fixed | `Variant = Primary / Secondary`; `Layout = Fixed / Scrollable`; primary icons above labels, secondary icons beside labels |
| `MaterialNavigationItem : Button` | Unselected, enabled | Label, normal/selected icon, badge, page content and data-template slots; normal Button Click/Command/CommandParameter/input/automation |

`MaterialNavigation` is an abstract ItemsControl. `Items` or `ItemsSource` must contain **MaterialNavigationItem controls**, not arbitrary data objects. The default non-virtualizing `MaterialNavigationPanel` preserves their identity. Use host-created/bound item controls for a data-driven collection. An item/control page cannot simultaneously belong to two parents. Page lifetimes and saved state are owned by the host; no hidden navigation stack is maintained.

### Selection and content contract

- **`SelectedIndex`**: StyledProperty, TwoWay by default; starts at -1 while empty, selects the first item on population. An out-of-range value in a populated control normalizes to the first item. Configure initial selection **after populating items** (or after binding the collection); no deferred future index is promised.
- **`SelectedItem`**, **`SelectedContent`**, **`SelectedContentTemplate`**: read-only observable DirectProperties. Item **`IsSelected`** is read-only and owner-controlled.
- Selecting synchronizes the item's state and its **`PageContent` / `PageContentTemplate`** before raising **`SelectionChanged`** (standard Avalonia SelectionChangedEventArgs with added/removed items).
- Activation commits selection before item **Click and Command**, then raises owner **`ItemInvoked`** with `MaterialNavigationItemInvokedEventArgs.Item`. Repeat activation raises Click/Command/ItemInvoked again, but not a fictitious SelectionChanged.
- Programmatic SelectedIndex and automation **Select** update content/selection without Click/Command/ItemInvoked. Automation **Invoke**, Enter/Space and pointer/touch activation execute the action. Handled Click suppresses Command according to Button's contract; ItemInvoked still reports the activation.
- Live changes to a selected item's PageContent or PageContentTemplate update the displayed page. Insertion/move preserves the selected item and adjusts SelectedIndex; removal clears the removed item's IsSelected and selects the nearest surviving index. Empty collections clear content and selection.
- Disabling an item or owner does not discard existing selection. Disabled/command-ineligible items cannot activate, are skipped by keyboard navigation, and reject automation actions. A host may programmatically select a disabled item to display saved state.
- `SetCurrentValue` preserves selection bindings during input. All UI/property/collection changes occur on the UI thread.

### Item slots

| Property | Contract |
| --- | --- |
| `Content`, `ContentTemplate` | Label. Default strings/objects wrap; Control labels are presented directly. A host template supports structured labels. Avoid independently interactive controls inside a destination label. |
| `Icon`, `SelectedIcon`, `IconTemplate` | Host-owned glyph, geometry/control or data. Null SelectedIcon falls back to Icon; read-only observable `DisplayIcon` reflects the effective icon. No bundled icon font is required. |
| `Badge`, `BadgeTemplate` | Decorative, non-hit-testable content slot. Use `MaterialBadge { Count = ... }` for counts or `new MaterialBadge()` for a dot. Counts/zero/99+ policy remain MaterialBadge's contract. |
| `BadgeDescription` | Optional **host-localized** accessible phrase appended to the destination name, e.g. “3 unread”. Updating/clearing it updates automation Name. Clear it when a zero/hidden badge is no longer meaningful; do not rely on the badge's decorative visual to convey important information. |
| `PageContent`, `PageContentTemplate` | Arbitrary host-owned selected content. A page may contain its own controls/actions and templates. Content, not just a status string, is presented by the default owner template. |

Give complex/icon-only labels `AutomationProperties.Name`; the BadgeDescription is appended to that explicit name too. Item Background/Foreground/fonts/templates keep Avalonia local-value priority. Host overrides then own affected selected/disabled appearance.

```xml
<m3:MaterialTabs xmlns:m3="using:Avalonia.Material3.Controls" Variant="Primary" Layout="Scrollable">
  <m3:MaterialNavigationItem Content="Overview 概览" Icon="⌂">
    <m3:MaterialNavigationItem.PageContent>
      <TextBlock Text="Actual overview content" TextWrapping="Wrap" />
    </m3:MaterialNavigationItem.PageContent>
  </m3:MaterialNavigationItem>
  <m3:MaterialNavigationItem Content="Library 资料" Icon="▤" BadgeDescription="3 unread">
    <m3:MaterialNavigationItem.Badge><m3:MaterialBadge Count="3" /></m3:MaterialNavigationItem.Badge>
    <m3:MaterialNavigationItem.PageContent>
      <StackPanel><TextBlock Text="Actual library content" /><m3:MaterialButton Content="Mark read" /></StackPanel>
    </m3:MaterialNavigationItem.PageContent>
  </m3:MaterialNavigationItem>
</m3:MaterialTabs>
```

preview.3 badge layout measures only the fixed24-DIP icon anchor, preserving icon/label baselines when dot/count changes. Dot placement is anchor-end−6/top; count placement end−12/top14−actual badge height. An item-local top/end ruler clamps overflow inside the allowed header item instead of negative-margin clipping. Very large caller-owned content remains subject to the explicit host constraints. Arbitrary Icon/Badge/Content templates and native destination actions remain intact. Independent raster and manual limits: [geometry remediation](../verification/manual-quality-geometry.md).

Bar uses SurfaceContainer and the pinned NavigationBarDefaults elevation0. Bar/rail active indicator uses SecondaryContainer, active icon OnSecondaryContainer and label Secondary; inactive icon/label OnSurfaceVariant. Tabs use Primary/OnSurface according to variant and SurfaceVariant divider1. All five typography metrics, semantic brushes, hover/focus/press alpha, disabled foreground, focus shape and effective state-layer duration are **live M3-02 resources**.

These are **minima**, not hard clipping heights: enlarged or long mixed labels grow/wrap. Every item target is at least48×48 under an unconstrained standard template. Too many fixed destinations to fit those targets require a host to choose Scrollable or an appropriate layout; deliberately clipping/constraining the parent below those sizes overrides the guarantee. Expanded rails consume their configured width; hosts must choose appropriate remaining page width. The library does not infer device classes or navigation breakpoints.

The built-in state layers and preview.3 **capsule/tab-underline selection paint** use effective `M3.StateLayerDuration`; selection paint uses `M3.Motion.EasingStandard` on the private coalesced render-frame Module. Selection/content/automation commit immediately; only decorative alpha/width changes inside the already fixed header envelope. Reduced motion snaps an active selection projection; hidden/detached work follows the shared frame lifetime. No new public clock/test hook or independent timer is added. Travelling-between-item indicators, Compose spring/frame/pixel identity and native shadow parity are **not** claimed. This is an Avalonia token/interaction projection, not a blanket upstream rendering-conformance claim.

## Keyboard, pointer, touch, focus and automation

- Bar/tabs: Left/Right, respecting RTL. Rail: Up/Down. Home/End select the first/last enabled visible item. Navigation wraps and automatically selects without executing action commands.
- The header is **one Tab stop**; Tab/Shift+Tab leave/reenter the header and selected page actions normally. Enter activates once; Space shows pressed state and activates on release. Right-click is not activation; captured release outside cancels.
- Mouse hover, focus-visible ring and press state layer are distinct public visual feedback. Touch can activate the transparent edge of the target. Standard ScrollViewer gestures/wheel scroll overflowing tab headers and tall rails; a touch drag cancels the button activation.
- Width, item layout, rail expansion, font and tab-layout changes retain the same item/control selection and focus. The focused/selected destination is revealed in the header. An **already focused** item is also revealed in enclosing host scrolling after resize; initial selection must not jump an outer gallery scroller.
- Owner automation: Tab for tabs, List for bar/rail; **ISelectionProvider**, single/required selection. Items: TabItem or ListItem, name/enabled/focus/selected state, **ISelectionItemProvider** and **IInvokeProvider**. SelectionContainer returns the owner. Select updates selection/content; AddToSelection rejects a second selection, and removing the sole selected item through the provider is rejected. Empty collections naturally return no selected peer.
- Selection/name property-change notifications are raised. Public peer and real Windows COM UIA evidence are delivered. A human Narrator/NVDA reading session, physical touch, Android/macOS/Linux, AOT and trimming are **not** verified by these results.

## Templates, gallery and dependent tickets

Owners use the MaterialNavigation style key and `Themes/Navigation.axaml`; items use MaterialNavigationItem. Public Theme/Template/ItemsPanel replacement is supported. An owner template needs `PART_ItemsPresenter`/ItemsPanel and SelectedContent/SelectedContentTemplate presentation. Optional `PART_HeaderScrollViewer` enables targeted automatic header scrolling; preserve one-stop keyboard navigation, focus/selection visuals and accessible targets. `HeaderWidth` is read-only observable geometry (NaN for horizontal headers, configured rail width otherwise), **not** another theme input. Private visual names are not a host extension contract.

`Gallery.Pages.ContentNavigationPage(MaterialTheme)` is a standalone package-only page: real pages/actions, counts and dots, ten explicit bar/rail/tab recipes, responsive rail expansion, primary fixed↔scrollable tabs, disabled input, mode/font/long labels and status/events. `samples/NavigationHost` executes that **compiled Gallery assembly**, not a source-library reference. #20 can add it to aggregate navigation. #17 can reuse the generic item/selection contracts without adding product routes to app bars/drawers.
