# M3-02 — Full theme input and token consumption contract

This extends (and preserves) the [#2 preview contract](../public-contract.md). All types are in `Avalonia.Material3.Tokens`; `MaterialTheme` is in `Avalonia.Material3.Themes`. Framework/package versions remain those of the preview; #20 owns the release version. Install the theme before creating content and update inputs on the **UI thread**. Inputs are StyledProperties; immutable records support `with`, binding and replacement at runtime.

## Color input precedence and platform boundary

```csharp
var theme = new MaterialTheme { SeedColor = Color.Parse("#006C4C") };
app.Styles.Add(theme);
// Use Avalonia's Application/Window.RequestedThemeVariant, not a second dark-mode flag.
window.RequestedThemeVariant = ThemeVariant.Dark;

// A host adapter can supply resolved platform roles, including arbitrary platform tones.
theme.DynamicColors = new MaterialDynamicColors(platformLightScheme, platformDarkScheme);
// Or supply six HCT key palettes:
theme.DynamicColors = MaterialDynamicColors.FromPalette(new MaterialPalette(
    new(145, 40), new(145, 16), new(205, 24), new(145, 4), new(145, 8), new(25, 84)));

// Restore brand generation, then the original explicit schemes:
theme.DynamicColors = null;
theme.SeedColor = null;
```

For **both modes**, precedence is `DynamicColors` → nullable `SeedColor` → the original `LightColorScheme` / `DarkColorScheme`. Updating the latter while an override is active stores a fallback; it does not cancel that override. Clearing overrides restores that fallback. The library does not inspect wallpaper, choose an OS preference, acquire fonts or call platform APIs. Platform acquisition belongs to the host. The original six-color constructor/deconstruction, static default colors, existing resources, and `with { Primary = … }` remain source-compatible. Additional roles in the six-color constructor use the standard light defaults; use `Dark with { … }` or a generator to customize a complete dark scheme. Independently overriding a role does not implicitly recolor its related roles.

`MaterialColorScheme.FromSeed(Color, bool isDark = false)` uses **MCU CorePalette.of**: source HCT hue/chroma, primary chroma max(48, source chroma), secondary 16, tertiary hue+60/chroma24, neutral4, neutral-variant8, error hue25/chroma84. `FromPalette(MaterialPalette, bool)` applies the pinned AndroidX ColorLight/DarkTokens v0_210 tone map. This is explicitly **not** MCU's newer SchemeTonalSpot, contrast-level resolver, content/expressive color variants or the 2025 color specification. No such option is advertised. Static `Light`/`Dark` remain the exact pinned AndroidX default palette, which is not numerically the same as regenerating its primary as a seed.

`MaterialHct.FromColor` converts sRGB to achieved hue/chroma/tone. `From(hue,chroma,tone).ToColor()` performs MCU sRGB gamut mapping; hue wraps, tone is [0,100], chroma is nonnegative, and all inputs must be finite. Alpha is ignored for generation and output is opaque. `MaterialTonalPalette.Tone(double)` supports fractional tones. `MaterialColorContrast.Ratio(foreground, opaqueBackground)` implements WCAG relative-luminance contrast after foreground alpha compositing; custom/platform colors are measured, not silently corrected.

### All 49 semantic roles

Each `MaterialColorRole` has a named init property, a `scheme.Get(role)` accessor and **both** resources `M3.{Role}Color` (`Color`) and `M3.{Role}Brush` (`ISolidColorBrush`). Consume via `DynamicResource`; C# lookup of a themed resource must pass the consumer's `ActualThemeVariant` to `TryFindResource`.

- Primary / OnPrimary / PrimaryContainer / OnPrimaryContainer; corresponding Secondary, Tertiary and Error quartets.
- Background / OnBackground; Surface / OnSurface; SurfaceVariant / OnSurfaceVariant.
- SurfaceDim, SurfaceBright, SurfaceContainerLowest, SurfaceContainerLow, SurfaceContainer, SurfaceContainerHigh, SurfaceContainerHighest, SurfaceTint.
- Outline, OutlineVariant, InverseSurface, InverseOnSurface, InversePrimary, Scrim, Shadow.
- PrimaryFixed, PrimaryFixedDim, OnPrimaryFixed, OnPrimaryFixedVariant; corresponding Secondary and Tertiary fixed quartets.

Fixed roles retain their tones in both modes. Background/OnBackground and SurfaceVariant remain available for compatibility, while new components should favor the surface-container hierarchy. Light/dark resources use Avalonia theme dictionaries and update **existing** consumers; they are not copied onto controls as local values.

## Typography — 30 complete roles

`MaterialTypography` has `FontFamily` (the preserved host fallback), optional `BrandFontFamily` / `PlainFontFamily`, positive finite `Scale`, and all 15 standard **plus 15 emphasized** `MaterialTypeStyle` properties. Each role has font family, size, line height, letter spacing and weight; defaults come from the pinned TypeScaleTokens **v0_103** (including its emphasized values). Display, headline and TitleLarge use brand; other roles use plain; a role's explicit `FontFamily` takes precedence. Size/line height/tracking scale together; weight does not. Null roles, invalid weights, nonfinite metrics, nonpositive size, line height below size, or overflowing scaled metrics are rejected before replacing the theme.

```csharp
theme.Typography = theme.Typography with {
    FontFamily = new FontFamily("Microsoft YaHei, Arial"), Scale = 2,
    LabelLarge = new MaterialTypeStyle(18, 24, 0.2, FontWeight.Bold)
};
```

Roles: DisplayLarge/Medium/Small, HeadlineLarge/Medium/Small, TitleLarge/Medium/Small, BodyLarge/Medium/Small, LabelLarge/Medium/Small; append `Emphasized` for the second set. Resources for every role are `M3.{Role}FontFamily`, `FontSize`, `LineHeight`, `LetterSpacing`, `FontWeight`. The old LabelLarge/BodyLarge font-size keys and `M3.FontFamily` remain. TextBlock classes such as `m3-body-large`, `m3-headline-medium` and `m3-body-large-emphasized` apply all five metrics and OnSurface foreground with live resources. MaterialButton now consumes the label role's family/size/weight; Window consumes the body role's family/size. Component templates own where line-height/letter-spacing resources are used.

Fonts are **not bundled**. Hosts must provide licensed assets and fallback suitable for Chinese/Latin mixing. Headless layout evidence does not establish glyph coverage on every OS.

## Shapes, elevation and states

`MaterialShapes` preserves both button radii, and adds the full rounded scale: None0, ExtraSmall4, Small8, Medium12, Large16, LargeIncreased20, ExtraLarge28, ExtraLargeIncreased32, ExtraExtraLarge48, Full. Resources `M3.Shape.Corner{Name}` are `CornerRadius`; Full uses the conventional saturated radius9999, clamped by Avalonia for ordinary component bounds. Also: CornerExtraSmallTop, CornerLargeTop, CornerExtraLargeTop, CornerLargeStart, CornerLargeEnd. Start/end resources describe LTR edges; a directional component must swap them in RTL. `GetRadii()` exposes the uniform scale. Negative/nonfinite radii are rejected. The four original button/focus resource names remain.

`MaterialElevation` has Level0..5 = **0,1,3,6,8,12 DIP**, plus overridable Shadow0..5 (`BoxShadows`). Resources: `M3.Elevation.Level{0..5}` and `M3.Elevation.Shadow{0..5}`. The heights are normative; the two-layer shadows are an Avalonia projection, **not pixel-identical Android shadows**. Shadow1 deliberately preserves #2's existing projection. Negative/nonfinite heights and invalid shadow geometry are rejected. Surface-container color roles provide the color hierarchy; elevation is not implemented as arbitrary opacity on content.

`MaterialStates` supplies live `M3.{PropertyName}` doubles: HoverStateLayerOpacity=.08, FocusStateLayerOpacity=.10, PressedStateLayerOpacity=.10, DraggedStateLayerOpacity=.16, DisabledContainerOpacity=.12, DisabledButtonContainerOpacity=.10, DisabledForegroundOpacity=.38. Opacities must be finite and [0,1]. `M3.DisabledContainerBrush` preserves #2's button alpha; `M3.DisabledSurfaceContainerBrush` uses the general .12 alpha; `M3.DisabledForegroundBrush` preserves OnSurfaceVariant at .38. MaterialButton's hover/press and disabled brushes now consume these inputs, as does its hover shadow.

## Motion — complete scales, not a hidden animation engine

`MaterialMotion` preserves StateLayerDuration=100ms and ReduceMotion. It exposes all 16 `DurationShort1..4` (50/100/150/200ms), `DurationMedium1..4` (250/300/350/400), `DurationLong1..4` (450/500/550/600), `DurationExtraLong1..4` (700/800/900/1000), and all ten cubic beziers: EasingEmphasized, EmphasizedAccelerate/Decelerate, Standard, StandardAccelerate/Decelerate, Legacy, LegacyAccelerate/Decelerate, Linear. `MaterialCubicBezier` stores four control points and `ToEasing()` creates a fresh Avalonia `SplineEasing`.

`Springs` accepts `MaterialSpringScheme.Expressive` (default), `.Standard` or a customized record. Both schemes contain Default/Fast/Slow **Spatial and Effects** spring pairs (`DampingRatio`, `Stiffness`, unit mass). These match pinned v0_14_0 spring tokens. The public pairs are parameters for component drivers, not an assertion that Avalonia's default tween renderer simulates Expressive springs.

Resources: `M3.Motion.{DurationName}` (`TimeSpan`), `M3.Motion.{EasingName}` (`SplineEasing`), `M3.Motion.DefaultSpatial`, `FastSpatial`, `SlowSpatial`, `DefaultEffects`, `FastEffects`, `SlowEffects` (`MaterialSpring`), plus `M3.ReduceMotion` and the preserved `M3.StateLayerDuration`. Reducing motion replaces **every effective duration** with zero and **every effective spring** with `IsInstant=true`; authored inputs are retained, so reversing the preference restores them. Drivers must read the effective resource and snap when IsInstant; this ticket does not claim that all later components have adopted those drivers. Negative durations, invalid bezier x coordinates, null schemes or nonpositive/nonfinite spring parameters are rejected.

## Gallery and package evidence

`Gallery.Pages.ThemeTokensPage(MaterialTheme)` is a standalone `UserControl` built only against the published package API. It has real M3 buttons for seed, light/dark, deterministic platform palette, 100/150/200% scale, shape and reduced-motion changes; mixed Chinese/Latin wrapping, enabled/disabled previews, all 49 color swatches, all 30 type roles, shape and elevation previews. #20 wires this page into the aggregate gallery. The page is already exercised by real headless mouse input at 320 and 1000 DIP and is compiled again through the fresh package, not a library ProjectReference.

Run `pwsh -NoProfile -File scripts/verify-theme.ps1` or the normal `scripts/verify.ps1`. Both fresh-package paths copy **no library source** and restore in a unique NuGet cache. Reference regeneration and exact red/green evidence are in [M3-02 verification](../verification/m3-02.md). No Android, manual screen-reader, real-desktop glyph/layout, native AOT or trimming result is claimed by this ticket.
