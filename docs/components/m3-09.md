# M3-09 — Cards, lists, badges and dividers

Issue [#7](https://github.com/ODtian/Avalonia.Material3/issues/7). Public namespace: `Avalonia.Material3.Controls`. Avalonia 12.1.3 / net10.0, current preview package `0.1.0-preview.2`. Install `MaterialTheme` before creating content as described in the [package contract](../public-contract.md). Full theme inputs and resources are described in [M3-02](m3-02.md); this component family has **no parallel color scheme or static semantic-color fallback**.

## Components and public consumption

| Type | Contract |
| --- | --- |
| `MaterialCard` | `Variant`: `Filled` (default), `Elevated`, `Outlined`. Primary interaction is opt-in: `IsInteractive=false` by default. `IsSelectable` toggles `IsSelected` on primary activation. `IsDragged` is a host-controlled visual state, not a cross-window drag-and-drop service. |
| `MaterialListItem` | Interactive by default. `Lines`: `One`, `Two`, `Three`, with **minimum**, not fixed, heights 56/72/88 DIP. `IsExpressive` adds the expressive state-dependent row shapes. |
| `MaterialList` | Rounded, non-virtualizing `StackPanel` collection. Public `Children`, `Spacing` and layout properties are retained. `CornerRadius` is uniform, finite and nonnegative; default theme uses CornerLarge. The list owns its rounded `Clip` geometry. Reorder interaction is for a **vertical** list of direct children. |
| `MaterialBadge` | `Count=null` is a 6-DIP activity dot; a nonnegative count is a minimum 16-DIP pill. `MaximumDisplayedCount=99`, positive; larger values display `99+` by default. This cap is configurable library policy, not a numeric value specified by BadgeTokens. `Count=0` hides the badge unless `ShowZero=true`. `DisplayText` is read-only and observable. |
| `MaterialDivider` | `Orientation`, `StrokeThickness` (default 1 DIP, positive finite), `InsetStart`, `InsetEnd` (nonnegative finite). `LineInset` is read-only and observable. A vertical divider needs a bounded parent height or explicit height. It is decorative and excluded from automation control/content views. Insets describe the horizontal left/right or vertical top/bottom edges in this delivery. |

`MaterialContentItem` is the abstract shared card/row foundation, not an unstyled standalone component. The concrete controls have actual Material ControlThemes, templates, state layers and input behavior.

### Content and action slots

The shared public slots are `Title`, `SupportingContent`, `Image`, `Leading`, `Trailing`, `Overline`, and inherited `Content` (body). Each has a corresponding `IDataTemplate` property: `TitleTemplate`, `SupportingContentTemplate`, `ImageTemplate`, `LeadingTemplate`, `TrailingTemplate`, `OverlineTemplate`, `ContentTemplate`.

- A slot can contain data, a string or an actual Avalonia `Control`. Default text templates **preserve actual controls**, including independently interactive actions; they do not stringify buttons or badges.
- Text defaults use BodyLarge for title/body, BodyMedium for supporting text and LabelSmall for overline/trailing supporting text. All five font metrics consume the full theme live. Long text wraps and grows; `Lines` never truncates it to an assumed number of physical lines.
- A host-supplied template/control owns its own font metrics, bounds, media, interaction and accessible name. Override individual text with a control/template or use the public per-role typography input; generated text consumes role resources rather than treating the parent's `FontSize` as a second typography scheme.
- The image slot expects an image control or host template; image loading, decoding, video playback and licensing remain host responsibilities. Pinned reference media layouts can be composed with 24-DIP standard / 20-DIP expressive icons, 40-DIP avatars, 56×56 images, 100×56 or 114×64 video previews. These are **host-supplied sizes**, not implicit coercions of arbitrary content. The automated gallery exercises the actual 56×56 image path; other media sizes are not claimed as separate decoder/player verification.
- Leading/image/trailing slots have 12-DIP separation; row side padding is 16 DIP, vertical padding 10 DIP. Optional empty slots do not retain their gap. Avoid unbounded or excessively wide custom trailing content in a narrow host. Combining the built-in auxiliary actions stacks them vertically, preserving their 48-DIP targets instead of consuming three adjacent columns.
- Slot content must have one visual owner. Do not place the same control instance in several slots/items.

### Item ownership, commands and selection

The library does not infer a business identifier. Put the item's stable identifier in `CommandParameter`, `Tag`, or the host model. Give each leading/trailing/revealed action its own command and its own identifier parameter.

`Activated` is a **direct routed event for primary activation only**. Nested actions do not raise it, do not execute the row/card command and do not toggle the row/card selection. The inherited Avalonia `Click` event still **bubbles normally**; filter its source if using it for delegation. Marking nested Click events handled would cancel the child's normal ICommand execution, so this library deliberately does not do that.

`IsSelected`, `IsExpanded` and `IsRevealed` default to TwoWay binding. Input uses `SetCurrentValue` so bindings survive both user changes and subsequent host updates. `MaterialList` does not impose single/multiple selection policy: the host decides which other items to clear or retain. Disabled state is inherited by nested actions. A primary command whose CanExecute disables a Button also disables that entire item; use `IsInteractive=false` when only primary activation should be suppressed while nested actions remain usable.

```xml
<!-- Inside a host with a typed item DataContext. Command parameters belong to this item. -->
<m3:MaterialListItem xmlns:m3="using:Avalonia.Material3.Controls"
                     Title="{Binding Title}"
                     SupportingContent="{Binding Description}"
                     Lines="Two" IsSelectable="True"
                     IsSelected="{Binding Selected}"
                     Command="{Binding SelectCommand}"
                     CommandParameter="{Binding Id}">
  <m3:MaterialListItem.Image>
    <Image Source="{Binding Preview}" Width="56" Height="56"
           AutomationProperties.Name="Image preview" />
  </m3:MaterialListItem.Image>
  <m3:MaterialListItem.Trailing>
    <m3:MaterialButton Content="Open" Command="{Binding OpenCommand}"
                       CommandParameter="{Binding Id}"
                       AutomationProperties.Name="Open this item" />
  </m3:MaterialListItem.Trailing>
</m3:MaterialListItem>
```

## Expanded, reorder and reveal contracts

These are real interaction paths, not only flags or renamed stock controls.

| Family | Public state/slots | Pointer/touch | Keyboard/automation | Host result |
| --- | --- | --- | --- | --- |
| Expanded | `IsExpandable`, TwoWay `IsExpanded`, `ExpandedContent`, `ExpandedContentTemplate` | Activate the named expand button. Detail participates in variable-height layout. | Alt+Enter toggles within the row; expand button supports ordinary Tab/Enter/Space/Invoke. Row exposes ExpandCollapse provider when expandable. | Only this row's expanded state/content changes; selection and primary command are not invoked. |
| Reorder | `IsReorderEnabled`, read-only `IsReordering`, `IsReorderActionsVisible`; `MaterialList.MoveItem(item,newIndex)` and `ItemReordered` | Drag the named handle vertically. At release, use the nearest **untranslated** child center, so different heights remain meaningful. A tap opens named Move up/down actions without moving/selecting. | Alt+Up/Down moves one child position. Invoke/Enter on the handle opens the same named actions; Escape closes them or cancels an active drag. | `Children` order is already applied when `MaterialListReorderedEventArgs` reports `Item`, `OldIndex`, `NewIndex`. The host mirrors that change into its domain collection. Identity/selection are retained. |
| Reveal | `IsRevealEnabled`, TwoWay `IsRevealed`, `RevealedActions`, `RevealedActionsTemplate`, `RevealWidth` (default 128, finite and at least 48 DIP); read-only `RevealTranslation`, `AreRevealActionsVisible` | Drag the primary body horizontally to expose a **trailing underlay**, not a detail row. Width/height stay stable. Drag updates the actual content offset and displays the underlay before release. Swiping never invokes a destructive action. | Alt+Right opens; named action-toggle button supports ordinary input/Invoke; Escape closes and returns focus to the row. Revealed actions have their own Button peers/commands. | Explicit activation of the revealed action owns its own item identifier. Selection/primary command are not fired by a swipe. |

The reveal adapter uses 16 DIP of movement slop and horizontal dominance greater than 1.5× vertical movement. A committed exposure of at least `min(48, RevealWidth/2)` DIP stays open. Smaller movement snaps back; moving right closes an open row. Secondary pointer buttons cannot reveal/select. Capture cancellation, detach and disabling input restore the settled state. These thresholds and nearest-center reorder are **declared Avalonia interaction policy**: the pinned token files specify styles, not these gesture algorithms.

Gesture rows use the normal default `ClickMode.Release`; overriding ClickMode to Press is outside the reveal gesture contract. Reorder temporarily translates the dragged row and restores its original transform on completion/cancellation, removal, disable or retemplating. Cross-list/native drag-and-drop, virtualization, momentum/fling-to-delete and automatic destructive swipe commits are not promised. Invalid/non-child/disabled/no-op/out-of-range `MoveItem` requests return false. Indices count all direct children; use homogeneous row collections when mirroring reorder to a data model.

Interaction enable flags gate user affordances, not the host's ability to set state programmatically. A host can keep detail/action content visible while disabling its gesture/toggle affordance.

## Accessibility and input

- Cards: Group when static, Button when interactive. Interactive selectable cards/rows expose Toggle state as the item selection contract. Rows expose ListItem role; the collection exposes List role. This is host-owned selection via Toggle, **not** an implicit Avalonia ListBox selection container or SelectionItem pattern.
- Names: explicit `AutomationProperties.Name`/label association takes precedence; otherwise title identifies the item before body text. For complex title templates, supply a meaningful name explicitly. Supporting strings supply help text unless the host overrides it.
- Toggle/Invoke uses the same primary selection/command/event path as normal input. Disabled automation invocation rejects through Avalonia's enabled checks; disabled pointer/keyboard interaction does not mutate the item.
- Auxiliary buttons are descendants of the named row in the public automation tree. Default English action names can be localized by replacing the public template parts. Gallery actions are explicitly named with their item identifier.
- Badge automation exposes Text role and the **full** count, not the capped display. A dot defaults to “New activity”; give the badge/associated target the meaningful host-specific name. The library does not guess the target's message semantics or announce host results automatically.
- Tab follows normal Avalonia navigation, including independent slot actions. Primary Enter/Space and release-in-target activation, outside-release cancellation, hover/pressed feedback and visible focus are retained. Revoking primary interaction during a press clears feedback without selecting.
- Core row/card targets are at least 48 DIP; line minima and auxiliary buttons can grow with typography. Custom small slot actions must provide their own accessible target.

Public peer/provider and automation-tree assertions are verified headlessly. **Narrator/NVDA/TalkBack, native UIA transport and physical input-device behavior have not been manually certified.**

## Template extension and gallery

Card and row `Theme`/`Template` are replaceable. Default list auxiliary parts are Buttons named `PART_ExpandButton`, `PART_RevealButton`, `PART_ReorderHandle`, `PART_MoveUpButton`, `PART_MoveDownButton`. Their handlers are attached/detached on retemplating. Keyboard primary behavior and peer providers remain on the control; a replacement template must display the slots/states, preserve targets/focus feedback, and bind the published reveal translation/visibility if it implements reveal. Omitting optional parts removes those pointer affordances, not the keyboard/state API.

`Gallery.Pages.ContentHierarchyPage` is a standalone public `StackPanel`, compiled through Gallery's **PackageReference**, not library source. It demonstrates three cards, independent item actions, dot/count badges, full/inset/vertical dividers, one/two/long three-line content, mixed 中文/English/日本語, images, disabled selection, expansion/reveal/reorder, and theme/font/list-width switches. `Result` exposes the host's item-specific result; `Rows` retains item identity while `List.Children` represents current visual order.

The package scenario actually instantiates the compiled page in a 740×1800 headless Window, switches the list to 320 DIP and font scale 1.5, changes theme, uses selection/action commands and keyboard reorder. This is not a claim that all content fits a short viewport. **#20 owns aggregate gallery navigation and scrolling-shell verification.**
