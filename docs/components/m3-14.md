# M3-14 — bottom and side information sheets

Namespace `Avalonia.Material3.Controls`. Install `MaterialTheme` before creating controls. Mutations and events are UI-thread operations. This extends the [overlay contract](m3-12.md), not a new window manager or application service.

## Pinned recipes and projections

The Compose baseline is AndroidX **11ece46a49d485c7644e53cb0684a611d7a0ec10**, not upstream main. Bottom surfaces consume live `SurfaceContainerLow`, elevation **1**, ExtraLargeTop **28/28/0/0**, and a horizontal **32 × 4** `OnSurfaceVariant` marker. The marker has an independently reachable **48 DIP** target and a `Secondary` keyboard focus ring. This is [SheetBottomTokens](https://github.com/androidx/androidx/blob/11ece46a49d485c7644e53cb0684a611d7a0ec10/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/tokens/SheetBottomTokens.kt), **not** the standalone vertical marker.

preview.3 keeps the larger transparent handle input allocation, but **state ink follows the marker's finite shape and focus ink stays in a40-wide affordance-local envelope** (side48 high / bottom40 high). Hover/focus no longer fills the entire sheet header. This does not change pointer allocation, detents, keyboard, focus or overlay lifetime. See [geometry remediation](../verification/manual-quality-geometry.md); native/density/manual evidence is reported separately.

preview.4 stock side sheets follow the pinned [MDC SideSheet anatomy](https://github.com/material-components/material-components-android/blob/60ff09436d5d477a4b9d02940f31eb01e1250620/docs/components/SideSheet.md): a TitleLarge headline and a trailing24-DIP close icon with a48-DIP native target, in a16-DIP padded header. Close consumes `DismissText`, native keyboard/Invoke and the existing dismiss/session path. Plain side-sheet content accepts horizontal drag while editors/actions and vertical scrolling retain their own input.

Hosts can explicitly put `MaterialSheetDragHandle { Sheet = owner }` in `Header` or a replacement template. This reusable vertical affordance retains [DragHandleTokens 7_0_1](https://github.com/androidx/androidx/blob/11ece46a49d485c7644e53cb0684a611d7a0ec10/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/tokens/DragHandleTokens.kt):4×48 idle,12×52 pressed/dragged and a48×56 target. Its `IsPressed`, keyboard/automation, cancellation and live state resources stay available.

The pinned Compose directory contains **no SideSheet / SheetSideTokens**. Side surfaces therefore use the coverage-pinned secondary Material Components Android commit **60ff09436d5d477a4b9d02940f31eb01e1250620**, [side tokens v34.0.0](https://github.com/material-components/material-components-android/blob/60ff09436d5d477a4b9d02940f31eb01e1250620/lib/java/com/google/android/material/sidesheet/res/values/tokens.xml): width **256**, standard Surface/elevation0/no corners; modal SurfaceContainerLow/elevation1/Large16 on the **inner** edge. Logical End swaps edges in RTL. Detached side surfaces use all-corner16 and [16 DIP margins](https://github.com/material-components/material-components-android/blob/60ff09436d5d477a4b9d02940f31eb01e1250620/lib/java/com/google/android/material/sidesheet/res/values/dimens.xml).

Modal scrim is supplied **once** by #13: `M3.ScrimBrush` at **.32** by default. Body typography is complete BodyLarge (family/size/weight/line-height/tracking), title is complete TitleLarge; choosing those slots is a library recipe because SheetBottomTokens does not prescribe a title/body typography. At scale2, body size/line-height/tracking are **32/48/1**, not a fixed-height 16-point label. Header/body/actions grow, and the whole shell becomes scrollable when fixed chrome cannot fit a short viewport.

Shape, semantic brushes, typography, state layers and elevation resources are dynamic. DefaultSpatial is the effective #3 spring resource. Sheet extent changes animate with a bounded unit-mass response; reduced motion snaps an active transition to the same accepted state. Opening and modal removal are instantaneous in this in-window projection: removal/focus/results are owned by #13, rather than delayed behind a second animation completion. Android shadows, nested-scroll physics, predictive-back transformations and Compose frame/pixel equality are **not** claimed.

## Standard really means normal layout

```csharp
var bottom = new MaterialBottomSheet {
    Title = "Details", Content = hostInformation,
    ExpandedExtent = 600, PeekExtent = 56
};
var layout = new MaterialSheetHost { Content = ordinaryPage, Sheet = bottom };
window.Content = new MaterialOverlayHost { Content = layout };
bottom.Expand(); // Collapse returns to the standard peek.
```

`MaterialSheetHost : ContentControl` has `Sheet`, `AvailableSize` and `ReserveVisibleExtent`.

- Bottom default reservation is the **peek** footprint while shown, including while expanded, matching a scaffold: at H800/S600/peek56, main height is **744**, sheet top is **744** at partial and **200** at expanded. `ReserveVisibleExtent=true` explicitly requests coplanar reflow with the current moving extent instead.
- Side always reserves the **current visible width**. At width1000, expanded256 leaves main **744**; while dragged to106, main becomes **894**. Hidden returns the space. Detached256 reserves **288**, including both16 margins, leaving main **712**.
- Standard sheets do not create overlay sessions, scrims, focus traps or background disabling. Merely setting `IsModal=false` on an overlay does **not** reserve layout space and is deliberately rejected by `sheet.Show`.
- `AvailableSize` on the standard host is a finite, nonnegative host-declared **layout rectangle at its origin**, clamped to actual bounds. Both ordinary content and sheet layout use it. Null uses actual bounded layout. A host chooses its own breakpoint and which sheet to put in `Sheet`; there is no hidden global responsive policy.
- Standard bottom initially partially expanded. Standard side initially hidden; call `Expand`. Side has only **Expanded/Hidden** stable states, not a fabricated peek state. `IsPartialEnabled` is irrelevant to side.

Use a bounded host, not an unbounded vertical outer ScrollViewer. The template's body already scrolls. `MaterialSheetHostPanel` is the public replacement-template layout primitive; provide exactly two children: ordinary content presenter, then sheet presenter, with `TemplatedParent` set to the host. Keep the panel physical-LTR and give each presenter the host FlowDirection, as the default template does; this avoids double mirroring.

## Modal presentation and the #13 contract

```csharp
var sheet = new MaterialSideSheet {
    Title = "Information", Edge = MaterialSheetEdge.End,
    Content = hostInformation, IsDetached = false
};
var session = sheet.Show(overlayHost); // End, Margin0, light-dismiss enabled
session.Closed += (_, result) => Observe(result); // cancellation has no value
// A host action may explicitly confirm a payload:
session.Close(hostChosenValue);
```

`MaterialBottomSheet.Show` defaults Bottom/Margin0. Side defaults logical Start/End/Margin0; a detached side defaults Margin16. `MaterialOverlayOptions` can override placement, finite margins/offset, initial/return focus and Escape/back/outside policies. Standard and modal forms share the content/template class, but never attach one instance simultaneously to both hosts.

For modal **available space / IME insets**, declare the actual in-window rectangle through #13 `options.Margin`. A sheet's optional `AvailableSize` is an additional **measurement cap**, not a new screen origin: it does not move the overlay's bottom/edge by itself. The gallery demonstrates a declared600×500 region with matching overlay margins. OS software-keyboard acquisition/insets remain the host's job.

The session keeps #13 LIFO, covered-request rejection, cancelable `Closing`, exactly-once completion, modal input/automation gating, focus containment and return/fallback. No second root Escape or focus trap is installed. `Session`, `IsModal`, `State`, `VisibleExtent`, `Offset`, `Detents`, `IsDragging` and `IsSettling` expose observable state. Dismissal never invents a host business value. Forced host teardown ignores a state/dismissal veto and finishes as `HostDetached`.

**Bottom collapse-first policy:** Back or Escape while Expanded with partial enabled first requests Partial and vetoes closing the session. The next request dismisses it. Outside/light dismissal requests Hidden directly. Side Back/Escape requests Hidden directly. Because #13 `RequestBack()` reports **completed presentation**, it returns **false** on a collapse-first request (or veto), even though the sheet may have changed state. A host back adapter must not navigate its ordinary page while `overlay.OpenCount > 0`; do not mistake that false result for an empty modal stack. The gallery's in-modal “Host back” action exercises this policy.

Choose Edge, detached mode and options before opening a modal. FlowDirection and resize remain live through #13. Edge/detached property assignments made while open configure the **next** presentation; the current immutable options/shape stay congruent. Reopen to adopt them. Direction/configuration changes cancel an active gesture instead of interpreting its next delta with the old axis.

## Detents and finite bounds

`ExpandedExtent=NaN` (default) measures the complete surface's natural content including handle/header/actions. Explicit nonnegative finite values are complete **surface** heights/widths, not body heights. Bottom default `MaxWidth=640`; override the ordinary Avalonia `MaxWidth` (for example Infinity) for a full-width host recipe. Side desired/default extent is256, independently clamped to available width.

`MinimumExtent` defaults56, `MaximumExtent` defaults Infinity (an explicit unbounded-cap sentinel), `PeekExtent` defaults56. Values are nonnegative; NaN is only the auto sentinel for ExpandedExtent. Contradictory minimum/maximum gives the minimum precedence, then actual available space always wins. Thus min120/max80/desired200 yields120 in a sufficient host, but only20 in a20-high host. Invalid negative/nonfinite dimensions are rejected; declared sizes must be finite. Zero content/minimum/peek safely yields zero geometry and can still be cancelled through the overlay host.

Independent reference examples use literal expected offsets, **not calculations from library accessors**:

| host height / full surface | modal Partial | modal Expanded | Hidden |
| --- | --- | --- | --- |
| 800 / 600 | 400 | 200 | 800 |
| 800 / 300 | 500 | 500 | 800 |
| 400 / 600 | 200 | 0 | 400 |

These follow the **new deterministic** [BottomSheet anchor path](https://github.com/androidx/androidx/blob/11ece46a49d485c7644e53cb0684a611d7a0ec10/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/BottomSheet.kt): Partial remains enabled for short content even when coincident with Expanded. This library does **not** expose the deprecated legacy auto-exclusion path. Growing formerly coincident Partial/Expanded promotes the accepted target to Expanded; viewport/content changes recompute anchors and snap stale transitions to valid finite geometry. Reconciliation is a configuration/layout operation, not a vetoable user gesture.

`IsPartialEnabled=false` immediately reconciles bottom to Expanded and removes the partial anchor; `Collapse()` then returns false. Standard `AllowDismiss=false` (default bottom) omits Hidden and prevents dragging below peek. Standard side defaults AllowDismiss=true. Modal Hidden is always supplied by its cancellation contract.

`State` is the **accepted target**; geometry can be between detents while `IsDragging` or `IsSettling`. `StateChanging(State,Cancel)` vetoes user/API changes; `StateChanged` reports accepted changes once, not every animation tick. `Expand`, `Collapse`, `Dismiss` return false for unavailable/no-op/disabled/reentrant/vetoed requests; session dismissal additionally rejects covered presentations. State is read-only rather than a TwoWay value silently coerced by layout; a host drives these operations and observes the direct property/events. Offset is relative to the measured available slot, not screen coordinates; ordinary Avalonia Width/MaxWidth can further constrain that slot.

## Input allocation, cancellation and automation

- Mouse only drags the named handle. Mouse wheel remains native body scrolling and never reinterprets a wheel as sheet drag.
- Touch/stylus handle drag waits for **8 DIP axis slop**. Bottom noninteractive body touch can participate: upward motion expands the sheet first, then passes leftover to its child viewer; downward motion consumes the child's current offset first and only uses remaining delta to collapse. Release decisions count **sheet-consumed travel**, not total finger travel, so child-only scrolling cannot collapse on release.
- Side handles use horizontal logical-edge motion; side body vertical panning remains native. A diagonal/cross-axis initial gesture is rejected. One pointer owns a gesture; a second contact cancels it.
- Child button/editor/selection/custom-focusable input is excluded from sheet body interception. Native TextBox editing, selection, IME, Enter and button invocation remain native. No child action implicitly confirms the sheet.
- `ScrollSource` may declare a specific viewer **inside this sheet's content**; otherwise the nearest viewer in the body pointer path participates. Replacement content/source releases the old active gesture. Unrelated viewers are not scraped.
- Default bottom positional threshold **56 DIP**, velocity threshold **125 DIP/s** come from [SheetDefaults](https://github.com/androidx/androidx/blob/11ece46a49d485c7644e53cb0684a611d7a0ec10/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/SheetDefaults.kt), not generated color tokens. `DragThreshold` / `VelocityThreshold` are host configurable. This bounded projection prefers threshold-crossing net sheet travel; a smaller move can settle by its latest consumed velocity. Side positional threshold is half its expanded width. Native touch momentum/Compose pre/post-fling physics are not replicated; body panning here is explicit delta allocation.
- `CancelDrag()` restores the last accepted target, clears dragging feedback and releases capture without settlement or confirmation. Capture theft, disable/gesture-off, retemplate, content/source replacement, second contact, detach and native window deactivation cancel. Capture loss is handled as a **direct** event, not a successful Thumb release. Resize during a drag clamps to the recomputed boundary; it cannot continue to an old off-window offset. Timers stop on detach/deactivation and reduced-motion changes.
- Handle click/tap toggles the next useful state; disabling drag still leaves click, keyboard and automation alternatives. Handle Up/Home expands, Down collapses bottom, End dismisses if permitted, Enter/Space toggles; side Left/Right follow physical opening/closing direction. Child keyboard input is not intercepted.
- Both sheet Pane and handle Button peers provide **ExpandCollapse**, with partial/expanded/hidden state; the handle also supplies Invoke. Side Collapse means dismiss. `HandleText`, `ExpandText`, `CollapseText`, `DismissText`, Title and ordinary AutomationProperties support host localization/naming. Pane ItemStatus identifies accepted/dragging state and modal/standard mode. Hidden/zero surface descendants are excluded from interaction; a visible affordance has a real focus ring. `IsDraggable=false` does not remove accessible alternatives.

## Slots and replacement templates

`MaterialSheet : ContentControl` preserves Content/ContentTemplate, Background/Foreground, ordinary typography, Width/MaxWidth/Padding/Theme/Template and standard Avalonia property/command binding on child controls. Added slots: `Title`, `Header/HeaderTemplate`, `Actions/ActionsTemplate`.

Replacement templates may supply a public `MaterialSheetDragHandle { Sheet = owner }`, native content/editor/actions, and an optional `ScrollViewer PART_BodyScroll` (public TemplatePart). Pointer/keyboard/automation/session behavior lives on the public owner/handle, not on private template children. A custom template owns its own accessibility, clipping, wrapping, short-height scrolling and visual roles; dropping every affordance cannot still be advertised as a draggable standard template.
