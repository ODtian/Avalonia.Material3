### Geometry targets (DIP)

`MaterialFabSize { Standard, Small, Medium, Large }` deliberately distinguishes Small FAB from Small **extended** FAB.

| Size | FAB container | FAB icon | Shape role | Extended container minimum | Extended icon | Icon/label gap | Extended type role | Extended horizontal padding |
| --- | ---: | ---: | --- | ---: | ---: | ---: | --- | --- |
| Standard | 56 | 24 | CornerLarge (16) | 56 | 24 | 12 | LabelLarge (14) | start16 / end20 |
| Small | 40 | 24 | CornerMedium (12); extended CornerLarge (16) | 56 | 24 | 8 | TitleMedium (16) | 16 / 16 |
| Medium | 80 | 28 | CornerLargeIncreased (20) | 80 | 28 | **12** | TitleLarge (22) | 26 / 26 |
| Large | 96 | **36** | CornerExtraLarge (28) | 96 | 32 | **16** | HeadlineSmall (24) | 28 / 28 |

Bold values use the pinned implementation corrections, not the uncorrected generated Large FAB icon32 or medium/large extended gaps16/20. Font values scale with the host typography; all role font/line-height/tracking/weight inputs are consumed. Shapes remain live host tokens rather than hard-coded radii.

Stock action templates reserve **5 DIP per edge for the focus ring and its gap**. Thus a baseline icon-only FAB occupies 66×66, Small 50×50, Medium 90×90 and Large 106×106 at rest, while the colored containers have the target dimensions above. The minimum input target is at least48. The transparent focus gutter is actionable, not an extra nested button. Slot spacing applies to measured action targets; the additional focus gutters mean visual inter-container gaps are not a pixel-for-pixel Android projection. Extended labels wrap and may grow the container height at large text; explicit host bounds/templates can override that adaptation.

## FAB and extended FAB public API

`MaterialFab : Avalonia.Controls.Button`:

- `Size` (StyledProperty, default Standard, validated enum).
- Read-only observable `PresentedSize`, `ContainerSize`, `IconSize`. Normally `PresentedSize == Size`. A standard associated whole-toolbar FAB is presented as Medium while collapsed; the host's stored `Size`/binding is never overwritten. An explicitly chosen Small/Medium/Large size remains the host's choice.
- `Content`/`ContentTemplate` is the icon slot. Preserve `Command`, `CommandParameter`, `Click`, `IsEnabled`, `Background`, `Foreground`, `CornerRadius`, `Template`, `Theme` and the normal Avalonia property precedence. Supply `AutomationProperties.Name` for icon-only content.

`MaterialExtendedFab : MaterialFab`:

- `Content`/`ContentTemplate` is the **label**, not the icon.
- `Icon`/`IconTemplate` is the independent optional icon slot.
- `IsExpanded` (TwoWay, default true); read-only `IconSpacing` and `ContentPadding`.
- Collapse removes only the label. Keyboard focus, accessible label, Click and command remain on the same action. With no icon, `IsExpanded` is coerced true so text-only content cannot collapse to a blank box; adding/removing the icon reevaluates coercion without dropping the host binding.
- Regular extended FAB activation performs its action; it does not toggle its own `IsExpanded`. Hosts decide when its label is shown.

```xml
<m3:MaterialFab Size="Large" Content="+"
                AutomationProperties.Name="Create document"
                Command="{Binding CreateCommand}" />
<m3:MaterialExtendedFab Size="Medium" Icon="+" Content="Create 新文档"
                        IsExpanded="{Binding ShowActionLabels}"
                        Command="{Binding CreateCommand}" CommandParameter="document" />
```

Default colors are PrimaryContainer / OnPrimaryContainer. Container elevation is level3, hover level4, focus/press level3; disabled styling uses the general disabled surface/foreground resources and removes elevation/state layers. Other host colors can be supplied through normal public Background/Foreground/theme inputs; this contract does not invent another color-scheme API.

## Multi-action FAB menu

`MaterialFabMenu : TemplatedControl`:

| Input | Contract |
| --- | --- |
| `Items` | Stable read-only `AvaloniaList<MaterialFabMenuItem>`; mutable action collection. Each item is a real control and retains its own content/templates/command/parameter/enable state |
| `IsExpanded` | TwoWay StyledProperty; default false; disabled menus cannot stay expanded |
| `TriggerSize` | MaterialFabSize, default Standard; all four initial sizes are supported; every opened trigger becomes the 56-DIP close recipe |
| `Anchor` | `MaterialActionAnchor { BottomEnd, BottomStart, TopEnd, TopStart }`, default BottomEnd; start/end mirror in RTL, top expands down, bottom expands up |
| `ToggleIcon`, `CloseIcon` | Independent content slots (default `+` / `×`) |
| `ToggleIconTemplate`, `CloseIconTemplate` | Independent data templates for those slots |
| `ExpandLabel`, `CollapseLabel` | Localizable non-empty accessible trigger names, default “Expand actions” / “Collapse actions” |
| Host layout | Normal Margin/alignment/min/max/bounds/FlowDirection remain public Avalonia inputs. Stock margin16 supplies a safe edge offset. Use a bounded Grid/DockPanel area for the menu; do not put it in an unconstrained stack if viewport containment is required |

`MaterialFabMenuItem : MaterialButton`: label in Content/ContentTemplate; icon in LeadingIcon/LeadingIconTemplate; default Medium/56-DIP container, icon24, gap8, horizontal padding24, TitleMedium, full shape, elevation3, PrimaryContainer/OnPrimaryContainer. Its normal inherited Button API is real, not silently ignored. Explicit inherited Size/Padding/Shape/Template overrides are custom host recipes, not another promised pinned menu-size family. Default string labels wrap.

The close trigger uses full shape, icon20, Primary/OnPrimary and elevation3. Items have4-DIP measured spacing; the close/action gap is8. A height-constrained scroll viewport keeps all actions reachable without moving the trigger out of its anchored area.

Opening focuses the first enabled visible action. Up/Down, Home/End navigate enabled actions and scroll them into view. Escape, outside pointer press and focus leaving the non-modal group dismiss it. Tab is not trapped. Action selection collapses and returns focus to the trigger **before Command executes**; an item's own Click handler runs earlier in normal routed-event order and may still observe the open state. Outside dismissal does not steal focus back from the newly focused host control. Disabling/detaching dismisses without attempting to focus an unavailable trigger.

The menu and trigger expose ExpandCollapse; trigger also retains Invoke. Items expose their Button name/enabled/Invoke semantics (and the inherited toggle semantics only if a host explicitly opts into a custom toggle action). Name and disclosure-state changes are live. Provider rejection on disabled controls is tested; exact native COM HRESULT mapping is not promised.

## Toolbars and associated FABs

`MaterialToolbar : TemplatedControl`:

- `Variant { Docked, Floating }` (default Floating), `Orientation` (Avalonia Horizontal/Vertical), `Color { Standard, Vibrant }`, `Anchor` (same logical corners as the menu).
- Stable read-only mutable `Items`, `LeadingItems`, `TrailingItems`: `AvaloniaList<Control>`. Collections are **actual action slots**; hosts supply MaterialIconButton/MaterialButton or other published controls. Custom content is not renamed or treated as a button automatically.
- `IsExpanded` (TwoWay, default true).
- `FloatingAction` optional `MaterialFab`; `FloatingActionPosition { Start, End }`, default End.
- `CollapseBehavior { ExpansionSlots, WholeToolbar }`, default ExpansionSlots; read-only `SurfaceIsExpanded`.
- `ExpandLabel` / `CollapseLabel` localizable non-empty disclosure names, default “Expand toolbar” / “Collapse toolbar”.

| Recipe | Layout, color and elevation |
| --- | --- |
| Docked horizontal | Host-width rectangular surface; min cross extent64; leading/trailing padding16; action spacing adapts4..32 without stretching individual action targets; elevation0 |
| Docked vertical | Directional projection: host-height rectangular surface; min width64; top/bottom padding16; same bounded action spacing; elevation0 |
| Floating horizontal | Full-shape min-height64; padding8 on all sides; edge margin16; fixed action spacing4; standard surface SurfaceContainer, content OnSurface/OnSurfaceVariant; elevation0 without associated FAB, level1 for the surface with FAB |
| Floating vertical | Same roles/shape/padding, minimum width64; actions expand/scroll along Y |
| Vibrant | PrimaryContainer / OnPrimaryContainer; selected MaterialIconButton actions use SurfaceContainer / OnSurface. Their own toggle state/command/focus behavior remains the published button behavior |

Containers may grow to retain focus gutters or scaled content;64 is a minimum, not an instruction to clip larger targets. Horizontal and vertical overflow are genuinely scrollable. Directional navigation/Home/End operate on Button actions, skip disabled actions, obey RTL and BringIntoView; other supplied controls retain their own keyboard handling and standard Tab behavior. Escape collapses the toolbar.

**ExpansionSlots** keeps core Items and the associated FAB available while hiding leading/trailing actions. Collapsing a focused expansion slot returns focus to the toolbar's visible disclosure action.

**WholeToolbar**, when a FAB is supplied, hides the complete surface and returns focus to the FAB. A standard FAB changes presentation targets56→80 and icon24→28 while closing; its stored Size remains Standard. Activating the collapsed FAB is disclosure only (no accidental primary Click/Command); activating it while expanded executes its normal primary action. Its ExpandCollapse provider can always reopen the surface; Alt+Down also expands from the collapsed FAB. If no FAB is supplied, WholeToolbar safely falls back to expansion-slot behavior so actions cannot become irretrievable. Replacing/detaching the associated FAB removes the extra provider and presentation context. A control cannot be hosted in two slots simultaneously.

```csharp
var toolbar = new MaterialToolbar
{
    Variant = MaterialToolbarVariant.Floating,
    Orientation = Orientation.Vertical,
    Anchor = MaterialActionAnchor.BottomEnd,
    CollapseBehavior = MaterialToolbarCollapseBehavior.WholeToolbar,
    FloatingAction = new MaterialFab { Content = "+" }
};
AutomationProperties.SetName(toolbar, "Editing tools");
AutomationProperties.SetName(toolbar.FloatingAction, "Create or expand editing tools");
toolbar.Items.Add(new MaterialIconButton { Content = "★", IsToggle = true });
toolbar.LeadingItems.Add(new MaterialIconButton { Content = "↶" });
```

## Motion, template extension and limits

Stock templates play the effective FastSpatial spring for label/toolbar layout and FAB container/icon geometry; FastEffects controls reveal alpha; the menu uses SlowEffects with nearest-trigger-first sequential clipping. Shapes use DefaultEffects through the shared normalized-corner driver; state layers use `M3.StateLayerDuration`. Closing slots immediately stop accepting input/focus/Invoke while their visual exit is still playing. Runtime ReduceMotion stops/snaps active size/reveal/shape drivers; preference reversal enables subsequent animation. Timers are bounded and stop on detach.

These are bounded unit-mass Avalonia spring projections. They are **not** a claim of Android frame/velocity/overshoot identity, Android shadow pixels, or the exact upstream per-item scale/stagger implementation. Menu items reveal sequentially through an anchored clip and group effects alpha; colors switch semantic roles, rather than promising upstream RGB interpolation. Host-selected spring values retarget from rendered geometry; no upstream velocity-continuity guarantee is made. `ContainerSize`/`IconSize`/CornerRadius describe current **targets**, while Bounds/rendered geometry can be intermediate during normal motion.

Local Avalonia values outrank themes. A custom Template must display its slots, provide safe target geometry, scroll/anchor as needed, retain visible focus and disclose the controlled expansion; private part names and internal animation controls are not extension API. Base Button input/commands/Invoke survive a custom FAB template, and public expansion providers/property state survive a custom composite template. Do not depend on stock template child names in application code.
