# M3-16 — application bars and navigation drawer

Namespace `Avalonia.Material3.Controls`; install `MaterialTheme` **before** constructing the window/content. These are real ControlThemes, not aliases of unthemed Avalonia controls. All mutation is on the UI thread. No routing/business service or extra runtime dependency is introduced.

## MaterialTopAppBar

`TemplatedControl`:

- `Variant : MaterialTopAppBarVariant` = Small; validated six enum members above.
- `Title : string?`, `TitleTemplate : IDataTemplate?`; optional host title template replaces, rather than duplicates, the standard text. `Subtitle : string?`; empty/null selects no-subtitle flexible heights. Host templates own their child semantics.
- `NavigationContent`/`NavigationContentTemplate`, `Actions`/`ActionsTemplate`: real content slots. Supply named `MaterialIconButton`/buttons/commands; no synthesized router or hidden back action.
- `CenterTitle : bool` = false; CenterAligned is centered irrespective of this flag; flexible forms may opt into centered title and subtitle, sharing the alignment used by the pinned title column. Centering is clamped between asymmetric navigation/actions. No overlap is required to maintain a mathematical center.
- `ScrollBehavior : MaterialAppBarScrollBehavior` = Pinned; `ScrollSource : ScrollViewer?` = null.
- Read-only `ExpandedHeight`, `CollapsedHeight`, `CollapsedFraction`, `IsScrolled`. Flexible subtitles are retained when collapsed using the small-bar LabelMedium role, alongside the TitleLarge title. Four-DIP spacing follows a present navigation target; the no-navigation title inset remains16.
- `Background` is the rest endpoint; `ScrolledBackground` is the scroll endpoint. Read-only `CurrentBackground` is the rendered blend. Two-row blend follows collapsed fraction; small/center changes at overlap >.01. Solid colors use deterministic RGBA interpolation; custom non-solid brushes switch at completion.
- `ResetScroll()` resets offset/fraction/overlap. Changing source/behavior resets to the new source, replacing/detaching unsubscribes the previous source. Reattaching that source re-observes it only while the bar is attached in the same TopLevel.
- `ApplyScrollDelta(double delta, double contentOffset)` is an optional **host nested-scroll adapter**, returning consumed DIP. Positive collapses; negative expands EnterAlways, or ExitUntilCollapsed when residual content offset is0. Arguments must be finite; contentOffset nonnegative. Do not bind ScrollSource and forward the same delta twice.

Automatic ScrollSource is an explicitly documented Avalonia **offset-driven projection**, not a Compose NestedScrollConnection. Pinned tracks content overlap without collapsing. EnterAlways follows signed Offset changes. ExitUntilCollapsed clamps absolute page Offset to expanded−collapsed; a downward wheel residual at source offset0 expands any adapter-retained collapse. Host adapters can pre-consume drag/scroll through ApplyScrollDelta and send only remaining delta to their content. This control does not intercept arbitrary window wheel input, invent fling physics, scrape gallery internals, or own page scroll restoration.

The [pinned AppBar implementation](https://github.com/androidx/androidx/blob/11ece46a49d485c7644e53cb0684a611d7a0ec10/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/AppBar.kt) informs heights, role switches and collision constraints. Projection differences: one visual/semantic title changes to TitleLarge at fraction≥.5 (no duplicate invisible title peers); instantaneous scroll layout rather than upstream travelling/crossfade/spring frames; Medium/MediumFlexible last-baseline bottom padding24 and Large/LargeFlexible28 follow the reference, reduced only when the nominal expanded row cannot fit them. Default layout rounding permits a half-DIP baseline raster difference. All font metrics remain live, and larger fonts/slots can grow collapsed/expanded heights.

Finite hosts cap long title/subtitle viewports around half available bar space (at least nominal recipe size), retaining real page space. **Full text is vertically scrollable, not discarded or ellipsized**, and remains accessible text. Unbounded parents do not apply that cap. Actions have a bounded horizontal scroller so surplus actions remain focusable/revealable; host action panels should use48-DIP targets and appropriate width. The default panel supports ordinary finite windows down to the documented200×300 scenario; it cannot promise page space below the sum of required action targets/bar minima.

Default top keyboard/mouse/touch action semantics are the supplied button contracts. Toolbar peer exposes title/name and expanded/scrolled/collapsed ItemStatus. Title text is not a button. Local templates/background/foreground use normal Avalonia precedence.

The default two-row template keeps separate TitleLarge/collapsed-subtitle and expanded-role lanes. Their typography and width stay fixed through collapse; top alpha follows(.8,0,.8,.15), bottom alpha follows1−CollapsedFraction, and semantics switch at fraction0.5. Single-row container color uses DefaultEffects; two-row color uses FastOutLinearIn progress and Oklab interpolation. Background color frames repaint the surface. The public four-child replacement-template panel contract and host TitleTemplate remain supported; singleton template results retain one live control with continuous placement.

## MaterialBottomAppBar

`TemplatedControl`: `Actions`/`ActionsTemplate`, `FloatingAction`/`FloatingActionTemplate`. Persistent80-DIP minimum, actual page commands and FAB; **not** destination navigation and no Selection pattern. Action overflow scrolls horizontally. Large/custom FAB/font/content can grow the bar rather than clipping targets. Default #9 standard FAB's56-DIP visual plus its focus margin yields nominal visual top12/end16 offsets. No implicit hide-on-scroll/accessibility-preference service is installed. Host can coordinate visibility deliberately.

## MaterialNavigationDrawer / MaterialNavigationDrawerLayout

Drawer derives **MaterialNavigation** from [M3-15](m3-15.md). Items/ItemsSource contain `MaterialNavigationItem` controls; labels, icons/selected icons, badge descriptions/templates, PageContent/templates, SelectedIndex TwoWay, SelectedItem/SelectedContent and selection/invocation events reuse that contract. Drawer labels are always horizontal; its inherited ItemLayout is not an additional drawer variant. The drawer template displays destinations, not the selected page. Host owns actual page presentation/history/title/actions/state.

Drawer properties:

- `Mode : MaterialNavigationDrawerMode` = Standard; `IsOpen : bool` TwoWay = true.
- `Title : string?` = "Navigation menu"; `Footer : object?`; `CloseText` = "Close navigation drawer" (nonempty, host-localizable).
- `BoxShadow : BoxShadows` defaults empty (elevation0); host can supply a semantic elevation shadow or explicit shadow and retain it across mode changes.
- `DrawerWidth : double` =360, validated240..360. Below240 host width the supplied layout/surface safely clamps to available width rather than creating negative page widths. Host chooses a breakpoint or narrower presentation, not the library.
- `IsStandardDismissible : bool` = true. False produces a permanent standard drawer: no visible close affordance/user-close gesture; host can still explicitly change IsOpen for layout adaptation.
- `IsGestureEnabled : bool` = true; read-only `DragOffset`, `Session`.
- `Show(MaterialOverlayHost, MaterialOverlayOptions? = null)` presents an **unparented Modal** drawer. Choose Mode before standalone Show. Default modal logical Start, margin0, scrim.32, Escape/Back/light-dismiss and first eligible destination focus. Explicit policies reuse #13 but must remain modal logical-Start. `Close()` returns actual close success, respecting top-only/veto/closed/permanent state.
- preview.4 uses pinned DefaultSpatial to open and FastEffects to close. Modal scrim follows travelled fraction; dismissible standard content moves by the same presented width. Positive open overshoot expands the surface toward the window edge while inverse scaling preserves content proportions. Accepted modal close completes the session/focus and releases the original control while an inert raster paints the remaining exit. Reduced motion resolves the same geometry immediately.

`MaterialNavigationDrawerLayout : ContentControl`:

- `Drawer`, `Content`/`ContentTemplate`; optional explicit `OverlayHost`, otherwise nearest ancestor MaterialOverlayHost.
- Standard/open drawer **really reserves/reflows** its measured width; standard/closed leaves full page width and no hidden destination Tab/UIA stops. Persistent/permanent is normal layout, not a modeless overlay.
- Modal/open transfers the same item/control identities into the #13 host, leaving page layout width intact. Switching back closes the session before reattaching in standard layout; a veto/covered session rejects the mode change. Selection and existing destination focus survive successful transfers.
- Modal layout anchors its session lifecycle to the layout even with Start placement; detach forcibly completes drawer/dependent suffix as AnchorDetached, not navigation/confirmation. Root detach follows #13 HostDetached.
- `IsEdgeSwipeEnabled` = false: explicit host opt-in for opening from logical-start24-DIP edge, avoiding conflicts with host platform back. Capture after horizontal8-DIP intent; release threshold .5 drawer width or400 DIP/s. Opening is a discrete commit, not predictive-back animation.
- Close drag supports touch/pen; mouse remains native button/light-dismiss input. Horizontal intent only; vertical destination scrolling stays native. Captured close drag uses same thresholds and follows RTL. Gesture disable, capture loss, resize, mode/flow change, retemplate, deactivation and detach cancel to current stable state, reset offset, and never invoke the dragged destination. A vetoed close restores the open surface.

Modal selection from **Invoke or SelectionItem.Select** closes the overlay successfully **before** committing destination selection/host navigation. Veto leaves selection/page/modality unchanged; Select rejects veto with InvalidOperationException, not a fake selection. Repeat Invoke still invokes normally. Provider Select does not fake Click/ItemInvoked. Host assignment to SelectedIndex remains deliberate programmatic state synchronization even while a drawer is closed/open.

Up/Down/Home/End move eligible drawer **focus only**; Enter/Space/pointer commit navigation. Single destination Tab stop, disabled skip; header/footer close/actions are additional stops. Modal Tab/Shift+Tab stays in the generic overlay scope. Light dismiss/Escape/host back and focus restoration use #13, never a second trap. A dialog above the drawer gets Back first. Hosts should test `OpenCount` before page Back: a vetoed overlay cannot fall through to underlying navigation.

Automation: List/ListItem; single Selection/SelectionItem, Invoke, drawer ExpandCollapse, full names plus host-localized badge descriptions and standard/modal open/closed ItemStatus. Cached background/lower-layer actions are gated by #13 without replacing original IsEnabled bindings. This is an **in-window** pane, not native OS WindowPattern/modal-window behavior.

Default template parts: drawer `PART_ItemsPresenter`, optional `PART_HeaderScrollViewer`, `PART_CloseButton` and `Border PART_Surface` for close-drag transform; DrawerLayout `PART_DrawerPresenter` and page `PART_ContentPresenter`. Host replacements must preserve named parts, focus/selection scope and appropriate typography/hit/automation semantics. Private descendant names and visual lookups are not application API.

## Package gallery and scope

`Gallery.Pages.AppChromePage(MaterialTheme, MaterialOverlayHost? windowOverlayHost = null)` is a bounded package-only host with real Home/Library/Details contents, retained saved result, return action, eight top recipes, bottom actions/FAB, page scrolling, disabled destination, nested dialog/back, theme/font/long text controls and responsive standard-permanent↔modal drawer. **720 DIP is example-host policy**, not a token. `samples/AppChromeHost` runs the compiled Gallery assembly through PackageReference.

Do not wrap this page's overlay root in another unbounded gallery ScrollViewer; place it in the available page viewport. In an aggregate shell, pass the bounded **window-root** host as `windowOverlayHost`: the page borrows it without replacing shell content, so modal drawers/dialogs also gate outer navigation/header and automation. OpenCount subscriptions are attached/detached with the page; its drawer session is anchored to the layout. The one-argument form owns its root for standalone use. #20 owns aggregate gallery wiring, release/API/AOT/platform acceptance. Evidence and truthful limits: [M3-16 verification](../verification/m3-16.md). No claim of human screen-reader announcements, physical touch/IME, Android predictive back/insets, platform-native shadow/frame/pixel/Compose nested-scroll equality, non-Windows desktop, AOT/trimming or actual App upgrade is made.
