# M3-17 — civil date and time forms

Additive preview API in `Avalonia.Material3.Controls`, Avalonia 12.1.3 / net10.0. Install `MaterialTheme`; mutation is on the UI thread. No calendar/time zone, business workflow, database, global culture, or secondary modal/focus service is installed.

## Covered forms

| Date | Time |
| --- | --- |
| Docked single calendar and range calendar | 12-hour analog clock, AM/PM |
| Modal single and range calendar, year/month navigation | 24-hour two-ring analog clock |
| Single and range native date input, docked or modal | 12/24-hour native keyboard forms |
| Switchable calendar/input, retained draft | Switchable clock/input, retained draft |
| Explicit inclusive bounds and endpoint predicate | Inclusive min/max; explicit overnight extension |
| Gregorian cultures, exact input/display formats | Culture period names, display format |

The clock supports vertical and horizontal composition (`Layout`); the host selects its responsive policy. The gallery chooses horizontal for a wide 24h host, vertical when opened in a narrow host. Changing layout, theme, font or size does not commit a form.

These are real Material surfaces: seven-column month geometry, year actions, selected circles/today outline/continuous range bands, analog dial/hand/two hour rings, large selected clock selectors and native time entry fields. They are **not** renamed Avalonia legacy DatePicker/TimePicker spinners.

## Form ownership and modal lifecycle

```csharp
var editor = new MaterialDatePicker
{
    SelectedDate = form.Date,
    DisplayMonth = new DateOnly(2024, 2, 1),
    Culture = CultureInfo.GetCultureInfo("en-GB"),
    InputFormat = "dd/MM/yyyy",
    MinimumDate = new DateOnly(2024, 2, 1),
    MaximumDate = new DateOnly(2024, 3, 31)
};
var result = await editor.ShowAsync(overlayHost);
if (result.Reason == MaterialOverlayCloseReason.Confirmed)
    form.Date = (DateOnly)result.Value!;
```

Use a bounded root `MaterialOverlayHost`. `Show` / `ShowAsync` require an **unparented** picker and use #13's `MaterialDialog`/session. The session's `Completion`, cancelable `Closing`, `Closed`, LIFO policy, Escape/back, containment, return focus and forced host detach are shared, not duplicated. Initial focus is the native start/hour input in input mode, month/hour selector otherwise. Explicit options override defaults. `Confirm()` returns false unless currently valid/enabled and the host accepts the close. `Cancel()` has no payload. A covered/vetoed/closed presentation does not publish a result. Repeated confirm is not a second form submission.

Results are **DateOnly**, **MaterialDateRange(Start, End)** or **TimeOnly**. Successful closure is the only form commit signal. `SelectedDate`, `RangeEnd`, and `SelectedTime` are **draft properties**, not an implicit transaction over the host's model. Do not TwoWay-bind them to saved values if cancellation must leave saved values unchanged. Reopen a fresh picker initialized from saved host values (as the gallery does), or explicitly reset a reusable unparented editor. Closure releases its dialog parent so reuse is possible.

For docked forms, put the same picker directly in normal layout; no scrim, overlay or focus trap exists. The host's Apply button checks `IsValid` and copies the draft. It also owns docked cancellation/reset and disabled Apply state. Never call `Show` on an already docked/parented control.

## Date contract

- `SelectionMode`: `Single` / `Range`; `Mode`: `Calendar` / `Input`.
- `SelectedDate`, `RangeEnd`: nullable `DateOnly`, TwoWay defaults. There is no local-midnight/UTC/DST conversion. `2024-02-29` stays that civil date on every time zone.
- Default inclusive bounds are **1900-01-01..2100-12-31**; hosts can explicitly use **0001..9999**. Invalid external selections are retained and marked invalid, not silently coerced to a different date or accepted. Inconsistent bounds disable all date actions/confirmation. Changing bounds/predicate revalidates current text/endpoints.
- `SelectableDate: Func<DateOnly,bool>?` is an endpoint UI/input policy. An interval's interior business availability is **not** inferred. Replace the delegate when its policy changes.
- `DisplayMonth` is independent from selection and normalized to its month's first day; bound changes clamp it to an available month when bounds are consistent. Navigation checks month edges without overflowing `DateOnly` extrema. `Today` is host-overridable for deterministic examples.
- `SelectDate(date)` executes the same endpoint path as a calendar action. None/completed range → start only; earlier date → new start; later/equal date → end. Equal endpoints are a valid one-day range.
- `NavigateMonth(offset)`, month heading/year actions, Left/Right/Up/Down, Home/End and PageUp/PageDown provide real navigation. Keyboard movement changes **focus**, not selection; native Space/Enter activates the focused date. RTL reverses horizontal arrows. Disabled dates cannot be activated. Native date/year peers expose full date/year names, Toggle state, availability, today/start/end/in-range ItemStatus.
- `IsValid`, `ValidationMessage`, `DraftChanged` are observable public outputs. An incomplete range, end without start, reversed interval, unavailable endpoint, invalid leap day or partial input cannot confirm.

### Culture and native editing

`Culture` affects explicit **Gregorian** month/week/full-date names, week start, parsing and formatting without changing process-wide `CurrentCulture`/`CurrentUICulture`. Culture is **not** an alternate calendar selector: notably `ar-SA` uses Gregorian civil dates here, not its default Hijri calendar. Use .NET cultures supporting a Gregorian optional calendar. Supported fixtures include `en-US`, `en-GB`, `zh-CN`, `de-DE`, and `ar-SA`.

`InputFormat` defaults to that Gregorian culture's short-date pattern; set an explicit exact .NET pattern for reproducible forms. `DisplayFormat` defaults to `ddd, MMM d`. Nonempty valid .NET format strings are a caller contract. Host strings/actions/errors come from immutable `MaterialDatePickerLabels` (replace with `with`); culture does not translate application labels or set `FlowDirection`.

| Explicit pattern | Fixture | Result |
| --- | --- | --- |
| `MM/dd/yyyy`, en-US | `02/29/2024` / `02/29/2023` | 2024-02-29 / invalid |
| `MM/dd/yyyy`, en-US | `03/04/2024` | 2024-03-04 |
| `dd/MM/yyyy`, en-GB | `03/04/2024` | 2024-04-03 |
| `yyyy/MM/dd`, zh-CN | `2024/02/29` | 2024-02-29 |
| `dd.MM.yyyy`, de-DE | `29.02.2024` / `29.13.2024` | valid / invalid |
| `yyyy/MM/dd`, ar-SA | `٢٠٢٤/٠٢/٢٩` | Gregorian 2024-02-29 |
| `MM/dd/yyyy`, en-US | `０２/２９/２０２４` | 2024-02-29 |

Unicode decimal digits are normalized **only for parsing**. Native text is never rewritten on each key; delimiters/paste/caret/selection/IME/undo belong to #6's public `MaterialTextField`. Formatted numeric display follows .NET (normally Western digits); full alternative-script formatting/digit shaping is not claimed. Inputs retain erroneous/partial text and errors for correction; invalid candidate properties become null. Changing culture/format preserves an invalid draft rather than erasing it; explicitly replace draft values when resetting. A culture/InputFormat change reparses retained invalid/unavailable native text under its new exact grammar, updating both range candidates before confirmation; it does not normalize the visible draft or replace native caret/Undo.

`StartInput` / `EndInput` are public native editors. Their inherited caret, selection, undo/clipboard/IME/read-only and template seams remain available. Changing `Mode` preserves candidates/month; attached date mode switches deliberately move focus to start input/month heading. Editor Enter does **not** implicitly submit.

## Time contract

- `SelectedTime: TimeOnly?` is a nullable, **minute-precision** civil value. External seconds/subminute values remain invalid rather than silently rounding; a deliberate edit/clock action establishes a minute value.
- `Mode`: `Clock` / `Input`; `Is24Hour`: false by default; `ActivePart`: Hour / Minute; `Layout`: Vertical / Horizontal. Changing 12/24 representation retains valid civil time/minute. Invalid draft text is not converted into a hidden old valid submission.
- `HourInput` / `MinuteInput` are public `MaterialTimeInputField : MaterialTextField`, with a genuine TimeInput native TextPresenter template. Hours are 1..12 or 0..23; minutes 0..59. `99`, `24:00`, `23:60`, missing values are invalid. `SelectedTime` becomes null while text is invalid; the internal last minute value is only a clock editing starting point, never an allowed stale Confirm result.
- AM/PM `SetPeriod(bool pm)` preserves minutes. Midnight 00:00 → 12:00 AM; noon 12:00 → 12:00 PM; 02:07 PM → 14:07. In 24h mode period controls are **absent**, not a disabled redundant pair.
- `SelectHour(0..23, advanceToMinutes = true)` and `SelectMinute(0..59)` are accessible/programmatic actions. Clock hour taps advance to minutes. Taps select 5-minute marks; continuous radial dragging, arrow keys and named +/- actions reach **every** minute. Hour 24h outer ring is 0..11, inner ring 12..23. Native visible marks are Toggle actions, not an inaccessible image.
- The dial owns one active radial pointer and uses public Avalonia gesture arbitration; its enclosing body remains independently scrollable. Touch/capture cancellation restores the pre-drag part value. Disabling/detaching/changing dial font/part invalidates the gesture. No private input platform, synthetic library key events or custom undo buffer is used.
- Valid hour editor Enter can move to minute; ordinary Tab/Shift+Tab, native IME and editing remain native. Minute Enter does not submit. There is no automatic two-digit focus jump.
- `MinimumTime` / `MaximumTime` are **library extensions**, not TimePicker token rules: inclusive, no bound means unbounded; min > max means an overnight union. Example 22:00..02:00 includes 22:00, 23:59, 00:00, 02:00, excludes 02:01. No hidden wrap of invalid input is performed.
- `Culture`, optional `DisplayFormat` (default `HH:mm` / `hh:mm tt`) and `MaterialTimePickerLabels` provide names/formats/localizable errors/actions. Time root has a named Group peer; inputs are native Edit/Value peers; dial marks and periods expose selected/enabled state and named operations. Root ItemStatus follows validity/value.

## Template, tokens and adaptation

Both pickers are `TemplatedControl`s. Read-only **`Surface`** is the full standard composition. A replacement ControlTemplate presents `{TemplateBinding Surface}` / `owner.Surface`; background/corners/scrolling may be customized without replacing native editing, selection or overlay result logic. `Surface` has a single visual parent: do not present it twice. Optional child themes can replace `MaterialCalendarDay`, `MaterialCalendarYear`, `MaterialClockNumber`, `MaterialTimeSelector`, `MaterialTimePeriodButton` and `MaterialTimeInputField` recipes. Replacing native input templates must retain its public TextPresenter contract. Host extension of the rendered body is not an excuse to omit input/focus/accessibility states.
