# M3-07 — Material text fields

`Avalonia.Material3.Controls.MaterialTextField` is a Material 3 text field built on **Avalonia `TextBox`**, not a second editor wrapped around a text box. Install `MaterialTheme` before creating the controls, as in the [package contract](../public-contract.md). Target: net10.0 / Avalonia 12.1.3. This is an additive preview API; the package version remains owned by M3-19 (#20).

## Basic use

```xml
<m3:MaterialTextField xmlns:m3="using:Avalonia.Material3.Controls"
                      Label="Display name / 显示名称"
                      PlaceholderText="中文 Atlas"
                      Text="{Binding DisplayName, Mode=TwoWay}"
                      SupportingText="Use the name others will see"
                      ShowClearButton="True"
                      ClearButtonLabel="清空名称"
                      ShowCounter="True"
                      MaxLength="40" />

<m3:MaterialTextField xmlns:m3="using:Avalonia.Material3.Controls"
                      Variant="Outlined"
                      Label="Email / 邮箱"
                      Text="{Binding Email, Mode=TwoWay}"
                      ErrorText="{Binding EmailError}" />
```

No Fluent/Simple theme is required by the library's text-field template. The standalone demo uses SimpleTheme only for its host's scrollbars and scrolling chrome.

## Public consumption contract

All new inputs below are Avalonia `StyledProperty` values and support binding, styles and local values. Outputs are read-only `DirectProperty` values. `Text`, its two-way default binding, validation, and editing APIs remain the inherited Avalonia contract.

| Member | Default / behavior |
| --- | --- |
| `Variant` | `MaterialTextFieldVariant.Filled`; enum values `Filled`, `Outlined` |
| `Label` | null; resting label becomes a smaller floating label on focus or content. Null/whitespace omits the label |
| `SupportingText` | null; wrapping helper text below the container |
| `ErrorText` | null; nonempty text establishes an error and replaces helper text |
| `IsError` | false; establishes an error without supplying a message; does not discard helper text |
| `HasError` | read-only; `IsError` OR nonempty `ErrorText` OR native binding validation errors |
| `EffectiveSupportingText` | read-only; first nonempty `ErrorText`, then first native validation message, then `SupportingText` |
| `PrefixText`, `SuffixText` | null; affixes shown with the expanded editor, not part of `Text`, selection or the counter |
| `ShowClearButton` | false; when enabled, clear is visible only for nonempty, enabled, editable fields |
| `ClearButtonLabel` | `"Clear text"`; nonempty accessible name, localizable by the host |
| `ShowCounter` | false; shows the current native length; it does not invent a separate input limit |
| `CounterText` | read-only; `"n"` when unlimited, `"n / limit"` for `MaxLength > 0` |

`CounterText` counts **UTF-16 code units**, the same units as Avalonia `MaxLength` and caret/selection indices. For example, `中😀` is 3 units, not 2 graphemes. Uncommitted IME preedit is not added to `Text` or the counter. Lowering `MaxLength` does not retroactively alter an existing value; the native editor owns enforcement on subsequent edits. `ShowCounter` does not establish a separate error state.

Native members remain available, including `Text`, `TextChanged`, `TextChanging`, `CaretIndex`, `SelectedText`, `SelectionStart`, `SelectionEnd`, `SelectAll`, `Clear`, `Undo`, `Redo`, `CanCopy`, `Copy`, `Cut`, `Paste`, `IsReadOnly`, `IsEnabled`, `PasswordChar`, `RevealPassword`, `AcceptsReturn`, `AcceptsTab`, `TextWrapping`, `MinLines`, `MaxLines`, `MaxLength`, `LineHeight`, `LetterSpacing`, font properties, selection/caret brushes, `Padding`, `Background`, `BorderBrush`, `BorderThickness`, `CornerRadius`, `Theme` and `Template`. Explicit local values follow Avalonia's normal style priority: a host overriding a state brush is responsible for that state's contrast.

## Slots and password / multiline forms

The inherited `InnerLeftContent` and `InnerRightContent` are the leading and trailing slots. They accept normal content/controls and Avalonia content templates. Interactive controls retain their own keyboard and automation behavior. Decorative content should not be made focusable. The built-in clear action is a **separate** trailing element; it does not overwrite `InnerRightContent`.

```xml
<m3:MaterialTextField xmlns:m3="using:Avalonia.Material3.Controls"
                      Variant="Outlined" Label="Amount"
                      PrefixText="¥" SuffixText="CNY">
  <m3:MaterialTextField.InnerRightContent>
    <TextBlock Text="✓" FontSize="24" Width="24" />
  </m3:MaterialTextField.InnerRightContent>
</m3:MaterialTextField>

<m3:MaterialTextField xmlns:m3="using:Avalonia.Material3.Controls"
                      Label="Password" PasswordChar="●"
                      RevealPassword="{Binding ShowPassword}"
                      ShowClearButton="True" />

<m3:MaterialTextField xmlns:m3="using:Avalonia.Material3.Controls"
                      Variant="Outlined" Label="Notes / 备注"
                      AcceptsReturn="True" TextWrapping="Wrap"
                      MinLines="3" MaxLines="5"
                      ShowCounter="True" />
```

A host may put an explicitly named visibility-toggle button in `InnerRightContent` and bind `RevealPassword`. There is no automatic password-reveal policy. The native editor masks input with `PasswordChar`, and its clipboard rules are retained: visually revealing a password also changes the native editor's copy behavior. The Material automation value provider stays protected **even when `RevealPassword=true`**. This is UI privacy, not encrypted storage; `Text` is still a normal managed string.

## Validation policy

The component presents feedback; it does not prescribe email/date/search rules, run validators or keep a second value. Validate in the host on editing, loss of focus, submit, or another chosen policy. Supply localized messages with `ErrorText`, or use the inherited `Text` binding's native data validation (`INotifyDataErrorInfo`, setter exceptions, etc.). Native attached `DataValidationErrors.Errors` / `HasErrors` are observed on the field itself. Only the first native error is displayed; an explicit `ErrorText` has priority. Clearing the errors restores helper text without changing `Text`.

```csharp
var email = new MaterialTextField { Label = "Email", SupportingText = "Include @" };
email.TextChanged += (_, _) => email.ErrorText =
    string.IsNullOrEmpty(email.Text) || email.Text.Contains('@') ? null : "Invalid address";
```

For search and date/time tickets, reuse this public `TextBox` editing surface and feedback policy; do not replace it with a custom key handler or a mirrored editor.

## Input, focus and accessibility

- Pointer/touch focus and caret placement, arrows, Shift+arrows, selection, clipboard, undo/redo and IME use Avalonia's native editing pipeline. Focused-editor key/text events are delegated unchanged to `TextBox`: no second editor, key remapping or committed-text rewriting. Bubbling key/text events from **focused interactive slots** are not passed into the parent's editor; otherwise Space/Backspace on a slot button could edit its parent value.
- Tab / Shift+Tab follow native focus navigation. Enter inserts a newline only with `AcceptsReturn=true`. `AcceptsTab` is opt-in and retains the native behavior.
- Read-only fields remain focusable/selectable/copyable, but cannot be typed into or cleared by the built-in action. Disabled fields keep their value, cannot be edited or activated, and are skipped by keyboard navigation.
- The clear action has a 48 × 48 DIP minimum target, an accessible name and keyboard-visible focus. Tab reaches it; Space/Enter or pointer activation first reconnects editor focus, then clears via native `Clear()`. Ctrl+Z restores the value through the native undo stack. Reconnecting before the deletion avoids losing undo history while the native IME client is detached.
- `MaterialTextFieldAutomationPeer` exposes **Edit** and `IValueProvider`, current read-only/enabled/focus semantics, and placeholder text. Name priority: explicit `AutomationProperties.Name` / `LabeledBy`, then `Label`, then `PlaceholderText`.
- Help text includes inherited/explicit help, effective helper/error text, and the counter when shown. Error item status defaults to `"Invalid"`. Name/help/status changes raise automation property notifications. Native value notifications are emitted without disclosing password text.
- Automation `SetValue` uses the same public text value and rejects disabled or read-only fields. For any nonzero `PasswordChar`, automation `Value` and its change-event values are empty strings, including while visually revealed.
- An intentionally unlabelled field should have an explicit accessible name. Do not use color as the only error feedback. Give interactive slot content its own accessible name.

Automated peer checks and real Windows UI Automation were exercised. **Actual NVDA/Narrator announcements, platform password flags and a real Chinese IME candidate session are not claimed as verified.** Avalonia's public peer API does not supply an `IsPassword` override here; this ticket supplies non-disclosing values, not a verified platform protected-edit flag. See the [evidence and manual protocol](../verification/m3-07.md).

## Layout, theme and template extension

The pinned reference is [AndroidX `11ece46a49d485c7644e53cb0684a611d7a0ec10`][tokens], `FilledTextFieldTokens` v0_210 and `OutlinedTextFieldTokens` v0_103, plus the [locked Material text-field component entry][material]. The visual container is at least 56 DIP high, has 4 DIP corners (filled: top only), a 1 DIP indicator/outline at rest and a 2 DIP focused indicator/outline. Helper/counter content is outside that 56 DIP container. Outlined fields reserve additional font-scaled space for the floating label.

Editor/resting-label/affix text uses the complete **BodyLarge** role; floating label/helper/counter text uses the complete **BodySmall** role (family, size, line height, tracking and weight). Defaults are 16/24 and 12/16 respectively. `MaterialTheme.Typography.Scale` grows all role metrics live. An explicit `FontSize` or `LineHeight` on the field changes the native editor only; use theme scale for a whole-component accessibility scale. Default editor padding is 16 DIP horizontally and 0.5 × editor font size vertically. Outlined notch placement uses half the actual supporting-role line height, so the label is centred on the stroke rather than shifted above it. Filled labels and helper text wrap. Outlined labels remain one line with ellipsis; their full text remains the accessible name. No fixed height is imposed on multiline input or helper text. Narrow windows still require the host to offer scrolling and enough room for its chosen interactive slot content.

Colors consume #3's full semantic scheme directly: `Primary`, `OnSurface`, `OnSurfaceVariant`, `Outline`, `Surface`, `SurfaceContainerHighest`, `Error` and `OnErrorContainer`. There are **no remaining ticket-local color fallbacks or parallel scheme APIs**. Shape consumes `M3.Shape.CornerExtraSmall` / `CornerExtraSmallTop`; the clear action consumes hover/focus/pressed state opacity resources. Disabled solid-role brushes are derived from the current `OnSurface` brush: filled container 0.04, filled indicator 0.38, outlined border 0.12; disabled content consumes `M3.DisabledForegroundOpacity` (default 0.38). These component-specific brush alphas follow the pinned text-field tokens.

The outlined label's notch is backed by `M3.SurfaceBrush`. Place outlined fields on that surface; for another hosting background, override that resource in the field's local scope or supply a host template with an appropriately backed notch. Explicitly styled slot controls remain responsible for their own colors and hit targets.

`Theme` and `Template` retain Avalonia's extension seam. Internal visual names and ticket-local resource keys are **not** consumption APIs. A replacement template must provide the inherited, public TextBox template part **`PART_TextPresenter` (`TextPresenter`)**, and should provide **`PART_ScrollViewer` (`ScrollViewer`)** to retain caret scrolling / `MinLines` / `MaxLines`. Forward native text, selection, caret, password, wrapping and font properties as in the default template. **`PART_ClearButton` (`Button`)** is an optional Material template part; supplying it wires the standard guarded clear/focus behavior. A replacement template owns its labels, slots, validation visuals, notch, hit target and focus styling. A scenario verifies editing through a replacement template with these documented parts.

The default editor scrolls its caret and supports native wheel scrolling, but does not render scrollbar chrome inside the field. Platform touch-selection affordances and platform context menus are not replaced by this ticket; a host can provide `ContextFlyout` using its menu theme. AOT, trimming and stable API baseline evidence remain #20's responsibility.

## Gallery and repeatable verification

`Gallery.Pages.TextFieldsPage(MaterialTheme? theme = null)` is a standalone public page, consuming only the packaged public API. Pass the installed theme to enable its 100%/200% role-scale action; by default it also discovers an application-level `MaterialTheme`. No theme is created or duplicated by the page. It demonstrates both variants, resting/focus/error/disabled states, mixed-language editing, validation and correction, prefix/suffix and leading/trailing slots, clear, counter, password visibility, read-only, multiline, unlabelled inputs, light/dark and 200% text. #20 wires it into aggregate gallery navigation.
