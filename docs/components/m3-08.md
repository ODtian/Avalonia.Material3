# M3-08 — Search and editable query chips

Namespace: `Avalonia.Material3.Controls`. Install `MaterialTheme` before constructing content. This is an additive net10.0 / Avalonia 12.1.3 preview contract; #20 owns release versioning, stable API baselines, AOT/trimming and aggregate gallery navigation. No additional runtime dependency, icon font, service, persistence, search history or product model is introduced.

## Actual search forms

`MaterialSearch : TemplatedControl` composes a **real `MaterialTextField` (`TextBox`)**, a native `ListBox` candidate-selection foundation, `MaterialChip` tokens and Material buttons. It does not implement a second text editor or interpret text into business query syntax.

| `Mode` | Presentation |
| --- | --- |
| `Bar` (default) | 56 DIP minimum rounded search header, SurfaceContainerHigh, level-3 shadow; opens into a search view with candidates |
| `View` | Initially open search view, docked 28 DIP corners, 56 DIP header, Outline divider and scrollable suggestions |
| `FilledAutocomplete` | Actual filled Material field and an anchored, inline SurfaceContainer / level-2 / ExtraSmall candidate dropdown |
| `OutlinedAutocomplete` | Actual outlined Material field, notch/floating label and the same autocomplete dropdown |

`ViewPresentation` is `Docked` (default) or `FullScreen`. An **open Bar/View** with FullScreen uses CornerNone and a 72 DIP minimum header. The view stretches inside a bounded host viewport; the host chooses its window/overlay placement and size. It is **not a library-owned modal window, navigation service or focus trap**. Autocomplete is a bounded inline anchored dropdown, not a platform-native OS popup or a separately positioned window. Parents must allow the desired expansion space/scrolling. These are explicit Avalonia presentation choices, not claims of upstream pixel/animation parity.

`IsOpen` is TwoWay, `Open()` focuses the editor and opens suggestions, and `Close()` dismisses suggestions, clears candidate selection and returns focus to the editor. Neither loses text/tokens or submits. Typing committed text while focused opens suggestions. Leaving the component dismisses them **without stealing focus back**. View starts open when its Mode is assigned. `HeaderHeight` is the read-only nominal 56/72 geometry (content/font growth may exceed it). `CandidateMaxHeight` defaults to 240, must be finite and at least 48, and bounds a genuinely scrollable candidate viewport.

## Query and host contracts

```csharp
var atlas = new MaterialSearchToken("atlas", "Atlas / 图集");
var search = new MaterialSearch
{
    Label = "Find documents / 查找文档",
    Candidates = new[] { atlas },
    SupportingText = "Choose a candidate or add the current text"
};
search.QuerySubmitted += (_, intent) =>
{
    // Immutable snapshot: all query tokens, remaining native text, selected token and explicit reason.
    ExecuteSearch(intent.Text, intent.Tokens, intent.Reason);
};
// Host owns retrieval, filtering, cancellation and validation. The library never fetches candidates.
search.Candidates = hostCandidates;
search.ErrorText = hostError;
```

| Property / method | Contract |
| --- | --- |
| `Text` | Nullable StyledProperty, TwoWay by default, native binding validation enabled. Bound directly to the editor; no key-to-string or caret mirroring |
| `Editor` | Read-only observable `MaterialTextField?`, null before template application. Native caret, selection, `SelectedText`, `SelectAll`, clipboard, `Undo`/`Redo`, MaxLength and IME are available here |
| `Candidates` | `IEnumerable<MaterialSearchToken>?`, host-owned suggestions. Null/empty means no candidates, never a synthesized history |
| `Tokens` | Non-null `IList<MaterialSearchToken>`; each instance starts with its own `AvaloniaList`. An observable collection updates visible chips on host changes; for plain lists reassign a new collection after changing it |
| `MaterialSearchToken(Key, Label)` | Immutable generic value; ordinal key identity for duplicate prevention, full display/accessibility label. Supply nonempty keys/labels |
| `SelectedCandidate` | TwoWay highlighted candidate, not an accepted value; acceptance requires it still belongs to current Candidates |
| `SelectedToken` | TwoWay single token selection for editing/emphasis, normalized to current Tokens. **All tokens remain in the query**; selection does not exclude unselected terms |
| `AddToken(token)` / `RemoveToken(token)` | Return false for duplicate/missing values, read-only collections, disabled or read-only searches. Key and label must be nonempty. Removing clears stale selection and returns editor focus |
| `AcceptCandidate()` | Returns false for stale/invalid candidates, disabled/read-only state or rejected token addition. Commits the current candidate according to CandidateAction, dismisses the list and returns native editor focus |
| `CandidateAction` | `AddToken` (default): add the chosen token and clear draft text. `ReplaceText`: put the candidate's label in native Text without adding a token. Set ReplaceText for conventional autocomplete; either behavior may be used with any form |
| `IsReadOnly` | Native editor remains selectable/copyable; token edits and candidate acceptance are blocked and token-removal actions hidden. A saved read-only query **can still be explicitly submitted** |
| `SubmitQuery(reason)` | Returns false when disabled or erroneous; otherwise raises QuerySubmitted. Valid reasons: Programmatic, SubmitButton, Keyboard; undefined enum values are rejected |
| `QuerySubmitted` | Bubbling routed event with `MaterialQuerySubmittedEventArgs`: read-only Text, immutable read-only snapshot of Tokens, SelectedToken and Reason. Later collection/text changes cannot alter the intent |

The built-in **Add token** action adds the current non-whitespace text as both key and label, without trimming/case normalization/parsing, then clears the draft. Hosts needing another identity scheme use `AddToken` explicitly. Duplicate keys use ordinal equality; host-supplied collections remain the host's responsibility (do not insert null, duplicate or invalid records). Programmatic changes, native editing, accepting a candidate, chip selection, filter/assist/suggestion actions, token add/remove and clear are **never implicit query submissions**. Native text undo does not double as token undo; candidate acceptance is an explicit programmatic value change, not a second undo stack.

`IsError`, `ErrorText`, `SupportingText` use the text-field feedback policy. `HasError` is read-only: host flag OR nonempty explicit message OR validation on the outer Text binding/attached errors OR native editor validation. `EffectiveErrorText` is the explicit message or first outer binding message. The editor presents explicit/outer errors before its own native validation message and helper text. Invalid queries cannot submit; values/tokens are preserved for correction. The host owns whether/when to validate and how to obtain or retry candidates.

## Chips

`MaterialChip : MaterialButton` retains Button Click/Command/CommandParameter, content/data templates, keyboard/pointer foundations and Invoke/Toggle automation, with its **own M3 chip template**, not a renamed action button. Use `ChipVariant`, not the inherited action-button `Variant`, to choose a recipe.

| `ChipVariant` | Action / selection / presentation |
| --- | --- |
| `Assist` (default) | Action; OnSurface label, optional Primary icon, flat outline or elevated SurfaceContainerLow |
| `Filter` | Two-state selection committed before Click/Command, selected check and SecondaryContainer/OnSecondaryContainer; flat or elevated |
| `Input` | Selectable token, optional 24 DIP avatar / 18 DIP icon, separate named removal action; flat only |
| `Suggestion` | Action proposing content; flat or elevated; does not select or submit by itself |

Properties: `ChipVariant`, `IsRemovable` (true, visible only for Input), `RemoveButtonLabel` ("Remove token"), `IsElevated` (false, ignored for Input), `IsDragged` (host-supplied drag feedback, not a drag recognizer), `Avatar` and `AvatarTemplate`. Inherited `LeadingIcon`, `TrailingIcon` and their templates, Content/ContentTemplate, IsChecked/IsToggle and Command remain available. Variant changes set the appropriate toggle purpose with SetCurrentValue; host overrides to inherited IsToggle are an explicit semantics customization. Assist/Suggestion normally advertise Invoke only; Filter/Input also advertise Toggle. Programmatic selection never activates an action.

`RemovalRequested` is a guarded bubbling routed event; it **does not remove a standalone chip from its host** or activate/toggle its primary action. The host owns removal. MaterialSearch's stock chips wire this to RemoveToken. Removal has an independent at-least-48×48 target, localized name and keyboard focus; disabling does not erase selection. Use noninteractive/decorative icon/avatar content; arbitrary interactive nested content requires host-owned semantics/layout.

Visual minimum height is **32 DIP**, shape is live CornerSmall (8 by default), icons 18 and input avatars 24. Every primary/removal target is at least 48 DIP. LabelLarge's complete font family/size/weight/line height/tracking updates live and long strings wrap rather than silently losing labels. Avatars should be host-supplied appropriately shaped artwork; the slot has a full-round backing and bounded content. Flat unselected uses OutlineVariant; selected filter/input uses SecondaryContainer, no outline. Elevated variants use level 1 (hover 2); selected flat filter hover is level 1; IsDragged uses level 4 and the drag state layer. Disabled label/icons derive from **OnSurface** and live disabled foreground opacity; outline/selected/elevated backgrounds consume the standard .12 surface-disabled brush. No whole-control fade substitutes for these semantics. Focus rings use Secondary; hover/focus/press/drag layers consume #3 state tokens and effective state-layer duration, including ReduceMotion. Chips do not advertise an upstream shape-morph spring animation.

Inherited action-button Size/Shape/Variant and nominal ContainerHeight/IconSize describe MaterialButton, **not chip geometry**; the chip template deliberately uses its own pinned 32/18/24 geometry. Theme/Template/local values retain Avalonia priority; explicitly masking a state brush/size makes the host responsible for that appearance and target guarantee.

## Keyboard, focus and automation

- Native left/right/Home/End, Shift selection, Ctrl+A, clipboard, delete/backspace, undo/redo and committed text use the TextBox pipeline unchanged. No empty-editor Backspace secretly removes a token.
- Editor Down/Up opens and highlights candidates (clamped list order), scrolling the highlighted row into view while retaining native editor focus, like an editable combo. Native ListBox Tab focus and arrows also remain available.
- Enter with an open highlighted candidate accepts it **without submitting**. Enter in the editor without an active choice is explicit Keyboard intent. Submit-button activation always means SubmitButton intent, even while a candidate is highlighted.
- Native nonempty IME preedit retains Enter/arrows/Escape; these keys are not converted into search actions. Automated tests exercise the real Avalonia client, not a mocked editor. Real platform Chinese candidate selection is a separate manual/platform check.
- Escape dismisses/returns editor focus; Tab/Shift+Tab can reach clear, slots, candidates, chip primary/removal and add/submit actions. Leaving does not trap focus. Slot Space/text events do not edit the editor or submit the query.
- Candidate pointer release inside the selected row accepts once; release outside cancels. Native Button press/release cancellation handles chips/actions. Disabled state rejects edits/actions, retains values and uses native focus navigation.
- Search peer: named Group for Bar/View, ComboBox for autocomplete; IExpandCollapseProvider with live state/events. Explicit AutomationProperties.Name/LabeledBy take precedence over Label. Editor: Edit/IValueProvider and text-field error/help semantics. Candidates: List/ListItem and native Selection/SelectionItem semantics with full labels. Chips: Button/Invoke and live Toggle for selection variants; removal is a separate Button/Invoke.
- Localizable search names: `Label`, `SubmitButtonLabel` ("Submit query"), `AddButtonLabel` ("Add token"), `ClearButtonLabel` ("Clear query"), `CloseButtonLabel` ("Close suggestions"), `RemoveTokenLabelPrefix` ("Remove", prepended to each full label). Give interactive host slots explicit names; do not rely only on error/selection colors.

Peer/headless behavior and actual Windows UIA/native key/mouse evidence are delivered. **Human NVDA/Narrator announcements, physical touch/Android/other desktop platforms, full Chinese IME candidate selection, AOT/trimming and final release are not claimed verified.**

## Template and slot extension

`LeadingContent` / `TrailingContent` are independently presented header slots; standard host DataTemplates remain available. `CandidateTemplate` is an optional IDataTemplate for the host-defined record; null restores the stock wrapping full-label template. Keep full accessible labels even when showing supplemental content.

A replacement search Template can provide the documented parts: `PART_Editor` (**MaterialTextField**, bind Text TwoWay and forward native/host error/read-only inputs), optional `PART_Candidates` (**ListBox**, bind Candidates and SelectedCandidate TwoWay), `PART_Tokens` (**ItemsControl**), and Button parts `PART_SubmitButton`, `PART_AddButton`, `PART_CloseButton`. Standard actions are rewired on application; old handlers are removed. The stock candidate template follows CandidateTemplate. A custom token ItemTemplate is retained, but the host must wire its own selection/removal through the public properties/methods. The stock chips are supplied only when no token template is supplied. Replacing the native field's own template must retain [M3-07's native editor parts](m3-07.md). Chip templates optionally provide `PART_RemoveButton` (**Button**) to wire guarded removal.

Other visual names/private dictionary keys are not API. Template authors own the visible shape, state layers, targets, focus ring, error/helper text, dropdown bounding/scrolling and native presentation bindings. A scenario verifies editing and explicit submission through a replacement search template.
