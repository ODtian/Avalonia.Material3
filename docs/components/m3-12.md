# M3-12 — Dialogs and the reusable overlay interface

Namespace **`Avalonia.Material3.Controls`**, Avalonia **12.1.3** / net10.0. Install `MaterialTheme` before content creation. All presentation, property and event mutations are on the UI thread. No additional runtime dependency or version bump; #20 owns release/API baselines.

## Present, edit, validate, return a result

Use a **bounded `MaterialOverlayHost : ContentControl` as the window/root content**, with all ordinary interaction inside its `Content`. It keeps overlays in the same visual, theme and scaling root rather than creating an unstyled OS window. Do not put the host inside an unbounded ScrollViewer or leave interactive siblings outside its scope. The supplied host template, Material surfaces, scrolling content and button templates are ready to consume; applications do not need to construct an overlay shell.

```csharp
var entry = new MaterialButton { Content = "Edit details" };
var host = new MaterialOverlayHost { Content = entry };
window.Content = host;
entry.Click += async (_, _) =>
{
    var editor = new MaterialTextField { Label = "Display name", Text = "Sample" };
    var dialog = new MaterialDialog
    {
        Title = "Edit details", Content = editor, ConfirmText = "Save",
        Mode = MaterialDialogMode.Basic // or FullScreen
    };
    dialog.Confirming += (_, args) =>
    {
        args.Cancel = string.IsNullOrWhiteSpace(editor.Text);
        editor.IsError = args.Cancel;
        editor.ErrorText = args.Cancel ? "A name is required" : null;
        args.Value = editor.Text;
    };
    var result = await dialog.ShowAsync(host, new MaterialOverlayOptions
    {
        InitialFocus = editor, ReturnFocus = entry
    });
    if (result.Reason == MaterialOverlayCloseReason.Confirmed)
        ConsumeHostValue(result.Value);
};
```

For **FullScreen** omit options to get the Mode-derived full-screen defaults, or explicitly set `Placement = FullScreen, Margin = 0` along with focus targets. Passing options is an explicit override, not a merge with Mode defaults. Choose Mode/placement before presenting; changing form requires closing and presenting again. Other dialog properties (title, content, actions, enabled confirmation, theme) may update while open. The library never writes application data, copies editing models, fetches services, or decides validation/business results.

### `MaterialDialog : ContentControl`

| Public property | Default / meaning |
| --- | --- |
| `Mode` | `MaterialDialogMode.Basic`; `FullScreen` is the other form |
| `Title` | nullable string; dialog accessible name unless explicitly overridden |
| `Icon`, `IconTemplate` | optional 24-DIP hero slot for basic dialogs; host supplies assets |
| inherited `Content`, `ContentTemplate` | arbitrary host content/native editing; default wrapping text template consumes BodyMedium (basic) / BodyLarge (full-screen) |
| `ConfirmText`, `CancelText` | nonblank `"OK"`, `"Cancel"`; host localizes |
| `ConfirmResult` | nullable host-owned payload, initially null |
| `IsConfirmEnabled` | true; disables the built-in confirmation action and `Confirm()` |
| `Actions`, `ActionsTemplate` | optional custom footer replacing basic default actions; full-screen retains header close/confirm and may add this footer |
| `IsOpen` | observable read-only DirectProperty |
| `Session` | current presentation, null after completion |

- `Show(host, options?)` returns a session immediately. `ShowAsync(...)` returns its completion task. A dialog instance can be reused **after** completion, not simultaneously. Use these methods, not `host.Show(dialog)`, to wire its built-in actions/session state.
- `Confirming` receives `MaterialDialogConfirmingEventArgs` with mutable `Value` (initially ConfirmResult) and `Cancel`. Validation can keep the same dialog/editor open. Then the session's `Closing` policy may also veto completion.
- `Confirm()` / `Cancel()` return whether completion succeeded. Covered/disabled confirmation does not commit. Cancellation never carries ConfirmResult or an edited value. The host decides whether to discard or preserve its own editor model; the library does not implement business rollback.
- No global/default Enter submission is installed. TextBox/IME owns Enter; focus an action and use Enter/Space to activate it. This avoids implicitly saving an editing form or consuming IME commit.
- Inherited public `Template`, `Theme`, bindings and content/data-template slots remain usable. Custom action buttons can call `Confirm()` / `Cancel()` without private child names. Replacement templates own their appearance/scrolling/touch targets/focus visibility. Default dialog template names and its adaptive panel are internal implementation, not an extension interface.

## Reusable presentation seam for menus, tooltips, snackbar, sheets, drawers and pickers

`host.Show(Control unparentedContent, MaterialOverlayOptions? options = null)` returns **`MaterialOverlaySession`**. The host must be attached; invalid policies/anchors/templates and already-parented content fail before registration. `OpenCount` is an observable DirectProperty. Presentations are a **LIFO stack**; covered sessions cannot complete until presentations above them finish. An upper modal disables normal content and all lower layers without overwriting the original controls' IsEnabled values or bindings. Modeless presentations above a modal remain inside the active modal interaction/accessibility scope.

### Session / results / lifecycle

- `Content`, immutable `Options`, `IsOpen`, `Task<MaterialOverlayResult> Completion`.
- `Close(object? value = null)` requests **Confirmed**. `Dismiss(reason = Cancelled)` requests a non-confirmation reason. Both return false for a covered/closed session, a veto or reentrant closing request.
- `Closing` receives `MaterialOverlayClosingEventArgs { Result, Cancel }`; the result is immutable. This is the generic validation/dismissal policy seam. Application commands and picker values remain outside the overlay implementation.
- `Closed` runs on the UI thread **after removal, modality/automation restoration and normal focus return**. The task is completed before this event; asynchronous task continuations do not run inline. A Closed observer may open the next presentation on normal completion.
- `MaterialOverlayResult(Reason, Value = null)` reasons: **Confirmed, Cancelled, Escape, Back, LightDismiss, HostDetached, AnchorDetached**. Only Confirmed supplies a payload. Teardown reasons are reserved and cannot be supplied to Dismiss.
- Detachment/reparenting of the host forcibly completes the entire stack with HostDetached. Removing an anchor forcibly completes its presentation and all presentations above it with AnchorDetached. Neither teardown is vetoable, and new presentations are prohibited during forced teardown. Even a throwing Closed observer cannot leave the remaining tasks pending; observer errors propagate as an AggregateException after forced cleanup. Normal observer/validation exceptions propagate as application errors; the completed session still has a result.
- Platform back bridges call `host.RequestBack()`; BrowserBack keyboard input also forwards to it. Its bool means the top session actually completed, not just that an input was consumed.

### `MaterialOverlayOptions` immutable record

| Property | Default / contract |
| --- | --- |
| `IsModal` | true; block lower interaction and automation navigation |
| `CloseOnEscape`, `CloseOnBack` | true; dismissal policy for top presentation only |
| `CloseOnLightDismiss` | false; opt in to a primary mouse/touch outside press-and-release; right-click is not a confirmation/dismissal |
| `InitialFocus`, `ReturnFocus` | null; explicit targets or first eligible content descendant / captured entry |
| `TakeFocus` | true for modeless; modal presentations always take focus |
| `RestoreFocus` | true; modeless feedback can opt out |
| `ShowScrim`, `ScrimOpacity` | true / .32; scrim only for modal. Hiding its color does not disable modality |
| `Placement` | `MaterialOverlayPlacement.Center` |
| `Margin` | 24 DIP on each edge, nonnegative finite |
| `Anchor` | null; Anchor placement requires a live descendant of this host |
| `Offset` | 0; finite physical in-window DIP displacement |

Placement enum: **Center, FullScreen, Bottom, Start, End, Anchor**. FullScreen fills the available host minus Margin; set Margin=0 for an edge-to-edge surface. Bottom places at the lower edge. Start/End fill the available height and use logical edges in host FlowDirection. The consumer supplies surface width, shape, drag handling, typography and actions; no sheet/drawer/menu business semantics are in this module. Anchor prefers below/logical-start, flips above when necessary, clamps to available host bounds and follows anchor/layout/window/RTL changes. This is **in-window placement**, not a native Popup that can extend outside window boundaries. Modeless outside input is not swallowed and may activate underlying content; modal outside input does not click through.

```csharp
// Transient feedback: no focus stealing/return. Lifetime/timers belong to the consumer.
var feedback = host.Show(snackbarContent, new MaterialOverlayOptions
{
    IsModal = false, TakeFocus = false, RestoreFocus = false,
    Placement = MaterialOverlayPlacement.Bottom, CloseOnEscape = false
});
// Modal sheet/drawer/picker: content supplied by the downstream component.
var sheet = host.Show(sheetContent, new MaterialOverlayOptions
{
    Placement = MaterialOverlayPlacement.Bottom, Margin = default,
    CloseOnLightDismiss = true, InitialFocus = sheetAction, ReturnFocus = entry
});
```

### Host template extension

The supplied host ControlTheme is sufficient. A replacement host template must register **`PART_ContentPresenter` of public type `MaterialOverlayContentPresenter`** and **`PART_OverlayLayer` of type `Panel`** in its name scope. Bind the former to host Content/ContentTemplate and place the latter above it, both filling the bounded host. The presenter is the reusable accessibility scope: disabling its interaction also hides descendants from automation navigation while preserving rendering. Ordinary ContentPresenter is not an equivalent substitute. Show rejects missing parts. Do not flatten automation children around visual parents; Avalonia's native fragment navigation requires a congruent hierarchy. Public host-template consumption is covered by a package scenario.

## Material recipe and adaptation

Normative pointers: [M3 dialogs](https://m3.material.io/components/dialogs/overview), [locked DialogTokens v0_210](https://github.com/androidx/androidx/blob/11ece46a49d485c7644e53cb0684a611d7a0ec10/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/tokens/DialogTokens.kt), [locked AlertDialog sizing/flow implementation](https://github.com/androidx/androidx/blob/11ece46a49d485c7644e53cb0684a611d7a0ec10/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/AlertDialog.kt). Baseline observation: 2026-10-04, per coverage matrix. The implementation projects these recipes into Avalonia, not upstream pixels/OS window APIs.

- Basic: SurfaceContainerHigh / OnSurfaceVariant body, OnSurface headline, Secondary icon, HeadlineSmall / BodyMedium / LabelLarge actions, CornerExtraLarge (28), elevation shadow level3 (6-DIP projection), 24 padding, icon24 / bottom16, title bottom16, body bottom24, action gap8. Nominal minimum width280 and maximum560; below 328-DIP host width it yields to available space instead of overflowing 24-DIP margins.
- Full-screen: Surface / OnSurface, no rounded perimeter or shadow, growing 56-DIP minimum header with close/title/confirmation, TitleLarge and BodyLarge, 24-DIP body inset. Not a maximized native OS window.
- Text action buttons are real #4 MaterialButton/IconButton templates: at least 48-DIP targets, focus rings, state layers, native mouse/touch/keyboard/Invoke. Confirm follows cancel horizontally and precedes it when stacked; localization/font scale can wrap/stack actions. RTL reverses logical horizontal ordering without double-mirroring edge placement.
- All type metrics, shapes, colors, state feedback and button motion consume live #3/#4 semantic resources; no parallel palette/font API. Light/dark, seed color and typography changes update existing surfaces. Explicit local property/template values have normal Avalonia precedence and transfer corresponding appearance responsibility to the host.
- Normally only the body scrolls and header/actions stay reachable. When translated/scaled header+actions exceed a short viewport, the entire shell becomes scrollable and the body remains bounded (160-DIP fallback viewport). Wheel, touch panning, Tab/BringIntoView can reach actions instead of silently clipping them. A 320×300 DIP, 200% translated-action scenario verifies this fallback. Hosts should still provide a usable viewport, not constrain interactive targets below 48 DIP.
- preview.4 MaterialDialog follows the AOSP Android16 Material.Dialog window recipe:220ms alpha0→1/Y20→0 with cubic(.2,0,0,1),150ms alpha1→0/Y0→−10 with cubic(.3,0,1,1). Reduced motion resolves the same endpoints immediately. Session completion, focus restoration and unparenting occur at accepted closure; an inert raster retains the exit artwork. Generic host content retains its own presentation.

## Focus, automation and platform evidence

Modal Tab/Shift+Tab cycles. Root-level programmatic focus escape is redirected, and non-interactive content gets a focusable container fallback. InitialFocus must be an eligible descendant; otherwise normal content focus is used. Normal close returns focus to a live enabled visible entry in the same root, otherwise to a lower presentation or first usable background control. Host detachment does not try to focus a closing root. Anchor teardown restores a surviving lower presentation when present.

Dialog automation: **Window role**, Title/explicit Name, ItemStatus `"Modal dialog open"`, `"Dialog open"` or `"Dialog closed"` unless host overrides ItemStatus; editor and action names/providers remain native. Modal background and covered layers disappear from automation navigation, while cached disabled Invoke is rejected. Parents remain congruent with the visual hierarchy: a real native run found and fixed E_FAIL caused by a flattened fragment tree. This in-window dialog does **not** advertise a native WindowPattern/OS-modal window provider.

Automated Windows UIA/SendKeys/native mouse and screenshot evidence is delivered. This does **not** establish human Narrator/NVDA announcements/reading order, physical touch hardware, Android back/IME/software-keyboard inset handling, macOS/Linux, Native AOT/trimming, upstream pixel/animation equality or final release/API stability. Platform adapters and those release/manual checks remain #20/host responsibilities. The native editor test commits the active desktop's IME preedit with Enter without implicitly submitting the form; it is not a comprehensive IME acceptance session.
