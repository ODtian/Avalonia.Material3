# M3-03 — Expressive buttons and icon buttons

This extends the [#2 frozen preview contract](../compatibility/preview1-contract.md) and consumes the complete [M3-02 theme contract](m3-02.md). Namespace: `Avalonia.Material3.Controls`. Install `MaterialTheme` before creating content; change controls/theme inputs on the UI thread. Current local candidate: `0.1.0-preview.2`; release/API evidence is in [M3-19](../verification/m3-19.md).

## Public controls and defaults

**`MaterialButton` still directly inherits Avalonia `Button`.** Its default remains small, round, filled, non-toggle. Existing content/templates, commands, parameters, events, enabled state, access keys, focus, local property precedence and template replacement continue to use Button's foundations. The automation peer remains assignable to `ButtonAutomationPeer` and keeps Invoke.

| Property | Type / default | Contract |
| --- | --- | --- |
| `Variant` | `MaterialButtonVariant.Filled` | Filled, Tonal, Elevated, Outlined, Text |
| `Size` | `MaterialButtonSize.Small` | ExtraSmall, Small, Medium, Large, ExtraLarge |
| `Shape` | `MaterialButtonShape.Round` | Round or size-specific rounded Square; not a sharp rectangle |
| `IsToggle` | bool / false | Activation changes a two-state selection when true |
| `IsChecked` | bool / false | StyledProperty with default TwoWay binding; selection is committed **before Click and Command** |
| `LeadingIcon`, `TrailingIcon` | object? / null | Optional, independently sized content slots |
| `LeadingIconTemplate`, `TrailingIconTemplate` | IDataTemplate? / null | Host-owned data templates for these slots |
| `ContainerHeight`, `IconSize`, `IconSpacing` | read-only observable double properties | Nominal size-specific template geometry, not measurements of enlarged/wrapped content |

Enum inputs reject undefined values. Programmatically changing `IsChecked` updates state/automation but does not raise Click or run Command. Turning `IsToggle` off hides the checked appearance and Toggle provider without clearing the stored value. `SetCurrentValue` preserves a selection binding when user input toggles it. A handled Click suppresses Command as in Avalonia Button. Command eligibility and `CanExecuteChanged` use the normal Button contract.

**`MaterialIconButton : MaterialButton`** reuses the same input, command, selection, size and shape contracts. Its icon-only template uses `Content` / `ContentTemplate` as a centered, size-constrained icon slot. It adds:

| Property | Type / default | Contract |
| --- | --- | --- |
| `IconVariant` | `MaterialIconButtonVariant.Standard` | Standard, Filled, Tonal, Outlined |
| `WidthMode` | `MaterialIconButtonWidth.Default` | Narrow, Default (uniform), Wide |
| `ContainerWidth` | read-only observable double | Nominal size/width-specific visual width |

Use **IconVariant**, not the inherited action-button Variant, to choose an icon recipe. Inherited leading/trailing slots are for action-button templates and are not displayed by the icon-only template. No bundled icon font or product-specific icon API is required: supply a glyph, geometry/control or data template. Hosts must give icon-only buttons a meaningful `AutomationProperties.Name`.

```xml
<m3:MaterialButton xmlns:m3="using:Avalonia.Material3.Controls"
                   Content="Save changes" LeadingIcon="+"
                   Variant="Tonal" Size="Medium" Shape="Square"
                   Command="{Binding SaveCommand}" CommandParameter="confirmed" />

<m3:MaterialIconButton xmlns:m3="using:Avalonia.Material3.Controls"
                       Content="☆" AutomationProperties.Name="Favorite"
                       IconVariant="Filled" WidthMode="Wide"
                       IsToggle="True" IsChecked="{Binding Favorite}" />
```

A host can change the icon/label when selection changes. It owns icon assets, font fallback/licensing and any checked/unchecked content semantics; the control owns selection and input. Complex/long labels can use a wrapping TextBlock or ContentTemplate and a finite available width/MaxWidth. Arbitrary oversized interactive content is not silently clipped or converted into a second action.

## Pinned sizes and shape policy

DIP values follow AndroidX commit **`11ece46a49d485c7644e53cb0684a611d7a0ec10`**: ButtonXSmall/Small/Medium/Large/XLargeTokens, XSmall/Small/Medium/Large/XLargeIconButtonTokens, ShapeTokens and ButtonDefaults. The generated XS action-button horizontal/gap tokens are corrected by that pinned **ButtonDefaults** implementation; this projection uses its **12 DIP padding / 4 DIP gap**, not the known uncorrected 16/8 generated values.

| Size | Visual minimum height | Action icon | Action gap | Action padding H / V | Text role | Square corner / pressed corner |
| --- | ---: | ---: | ---: | --- | --- | --- |
| XS | 32 | 20 | 4 | 12 / 6 | LabelLarge (14/500) | Medium 12 / Small 8 |
| S | 40 | 20 | 8 | 16 / 8 | LabelLarge (14/500) | Medium 12 / Small 8 |
| M | 56 | 24 | 8 | 24 / 16 | TitleMedium (16/500) | Large 16 / Medium 12 |
| L | 96 | 32 | 12 | 48 / 32 | HeadlineSmall (24/400) | ExtraLarge 28 / Large 16 |
| XL | 136 | 40 | 16 | 64 / 48 | HeadlineLarge (32/400) | ExtraLarge 28 / Large 16 |

All five typography metrics (family, size, weight, line height, tracking) use the corresponding **live M3-02 role resources**, not a second font scale API. Host per-role overrides and Scale update existing controls. Content growth may increase visual and target heights. The S default padding and original button radii remain compatible with #2.

| Icon size | Icon | Narrow width | Default width | Wide width |
| --- | ---: | ---: | ---: | ---: |
| XS | 20 | 28 | 32 | 40 |
| S | 24 | 32 | 40 | 52 |
| M | 24 | 48 | 56 | 72 |
| L | 32 | 64 | 96 | 128 |
| XL | 40 | 104 | 136 | 184 |

Every input target is at least **48×48 DIP**, including an invisible transparent portion outside small/narrow visuals. The template reserves five DIP around the container for the focus ring (3 DIP stroke plus 2 DIP gap); S therefore normally occupies 50 DIP vertically. XS visuals stay 32 DIP rather than being stretched to fill their larger target. Explicit host dimensions, margins, templates and parent clipping can override these guarantees; do not deliberately constrain the control below its accessible target.

Round shapes use the live saturated `M3.Shape.CornerFull`, normalized to actual bounds before spring interpolation. **Compatibility exception:** the S action button continues to use `M3.ButtonCornerRadius` (default 20), and XS/S action press uses `M3.PressedButtonCornerRadius` (default 8). This preserves the #2 shape input/API. For an adaptive full-round S container, the host can set `theme.Shapes = theme.Shapes with { ButtonCornerRadius = theme.Shapes.CornerFull }`; pressed styling continues to work. Square, larger pressed and icon shapes use the full shape scale. Icon toggle selection changes round → square and square → round; action-button selected shapes retain their respective round/square form. Pressed shape takes precedence over checked shape.

## Recipes, feedback and motion

Color/state/elevation resources come from MaterialTheme, including seed/platform input precedence and light/dark switching. No component-local palette shadows the full semantic scheme.

| Recipe | Normal / toggle-off | Toggle-on |
| --- | --- | --- |
| Filled | Primary/OnPrimary; toggle-off SurfaceContainer/OnSurfaceVariant | Primary/OnPrimary |
| Tonal | SecondaryContainer/OnSecondaryContainer | Secondary/OnSecondary |
| Elevated action | SurfaceContainerLow/Primary; elevation 1, hover 2 | Primary/OnPrimary |
| Outlined | transparent/OnSurfaceVariant, OutlineVariant stroke | InverseSurface/InverseOnSurface, no stroke |
| Text action | transparent/Primary | Same text recipe; checked semantics/content remain host-observable |
| Standard icon | transparent/OnSurfaceVariant | transparent/Primary |

Outline widths are 1/1/1/2/3 DIP by size. Filled/tonal action hover uses elevation 1; pressed returns to 0. Elevated action keeps elevation 1 while pressed. Icon, outlined and text recipes have no hover elevation. Disabled filled containers use the button OnSurface alpha (.10 default); labels use OnSurfaceVariant × .38. Disabled icon foreground is OnSurface with .38 applied to the icon only. Unselected outlined/text/standard containers remain transparent. Hosts can override all relevant state/elevation inputs live.

Hover, focus and press layers use `M3.HoverStateLayerOpacity`, `FocusStateLayerOpacity`, `PressedStateLayerOpacity`. Their alpha transition uses `M3.StateLayerDuration`. The container and focus ring use the effective **`M3.Motion.DefaultEffects`** unit-mass spring pair, as in the pinned Button/IconButton interaction-shape implementation. `IsInstant` snaps immediately; changing ReduceMotion during playback stops it and applies the current target. The internal driver normalizes saturated radii before interpolation, retargets from the rendered shape, stops at rest, and cancels timers on detach. Layout changes establish the new finite shape immediately. Extreme custom numeric inputs or transitions exceeding ten seconds fall back to the target rather than leave an unbounded driver active. This is an Avalonia spring projection, not a claim of upstream frame/pixel-identical Compose animation or velocity-identical retargeting.

Local property values have Avalonia priority. An explicit local Background, Foreground, CornerRadius, Padding, FontSize, etc. can mask theme/state setters; hosts then own the affected appearance. Theme/Template replacement retains Button input and automation but must preserve content presentation, target area, state layers, selection feedback, focus visibility and motion preference behavior. Template child names and the internal shape driver are **not public extension API**.

## Input and automation

- Mouse/touch press and in-bounds release activate once; captured release outside cancels. Right-click does not activate the default action.
- Tab/Shift+Tab use Avalonia navigation; keyboard focus has a separate visible ring. Enter activates; Space shows press and activates on release. ClickMode/access-key/default/cancel behavior remains Avalonia Button behavior.
- Disabled or command-ineligible controls do not activate; disabling does not clear selection.
- Name comes from Button's content contract or explicit AutomationProperties.Name; role is Button, enabled/focus state are live, Invoke runs the same action.
- IsToggle exposes IToggleProvider with Off/On, selection change events and Toggle executing the same action. Non-toggle controls do not advertise Toggle. Provider availability is cached thread-safely because native UIA queries it off the UI thread.
- Headless/public peer tests and a real Windows UIA/keyboard/native-mouse smoke are delivered. A human NVDA/Narrator session, physical touch hardware, Android and other desktop platforms are **not** claimed as verified. Avalonia 12.1.3's Windows COM bridge projects a rejected disabled Invoke as a generic exception in the observed run; no exact HRESULT mapping is promised here.

## Gallery, package reproduction and #20

`Gallery.Pages.ExpressiveButtonsPage` is a public standalone StackPanel built against PackageReference only. It demonstrates every action/icon recipe, normal/off/on/disabled states, all sizes, both shapes, all icon widths, content slots, command results, mixed/long labels, 200% text, mode/shape/enabled/motion changes. #20 can put it in aggregate navigation without library source references. `samples/ButtonsHost` already hosts that actual Gallery assembly page in an independently packaged desktop consumer, so it can be exercised before aggregate wiring.

The button dictionary supplies a minimal genuine ScrollViewer presenter/gesture foundation so the examples can scroll to all rows instead of relying on ContentControl's non-scrolling fallback. Scrollbar skinning is not advertised by this ticket; hosts/#20 can replace that foundation with their broader scroll theme.

```powershell
pwsh -NoProfile -File scripts/verify-issue4.ps1
pwsh -NoProfile -File scripts/verify-issue4.ps1 -DesktopSmoke
# -KeepSandbox leaves the isolated, freshly restored consumer directory for interactive use.
```

The verifier first tests source, then packs to a **new local feed**, copies consumers/scenario sources/fixtures but **no library source project**, restores with a **new NuGet cache**, runs the linked suite and actual compiled Gallery page, and builds ButtonsHost. DesktopSmoke launches that fresh executable, exercises native UIA/mouse/keyboard, captures screenshots and closes it. Do not run new scenarios against a stale cached preview package. Normal/theme verification scripts also include the new scenarios.
