# Avalonia Material 3 Expressive 控件库规格

Status: ready-for-agent

日期：2026-10-04。规格版本：1.0。归属：独立 M3 仓库。

## Problem Statement

用户需要一套完整、标准、可复用的 Avalonia Material 3 Expressive 设计系统，能够统一表达动态配色、字体、形状、组件状态和动效，并用于本 App 及其他 Avalonia 应用。

该设计系统需要具备独立的组件展厅、测试、文档、版本和包发布流程。客户端通过明确的包契约使用它，使通用设计系统与 Pixiv 产品功能各自持续演进。

## Solution

建立独立 M3 仓库，交付现代 Avalonia 机制实现的令牌、完整标准组件、主题输入契约、组件展厅、使用文档与版本化包。实现以日期锁定的 Material 3 Expressive 规范为基线，通过完整覆盖矩阵验收。

本 App 消费 M3 的公开 API 和发布包，并在真实客户端场景中验证集成。M3 自身使用通用示例内容、主题输入和交互场景验证组件。

## Implementation Decisions

- M3 使用独立 Git 仓库与 GitHub Issues，拥有自己的词汇表、ADR、规格、版本及发布流程。
- 采用 C#、Avalonia 12 稳定基线与现代 ControlTheme、ControlTemplate、TemplatedControl、StyledProperty、伪类及编译绑定。
- 依赖边界为 Avalonia 与通用设计系统能力；Pixiv 数据、会话、下载、搜索历史和传感器业务属于 App。
- 主题公开契约表达色彩方案、字体、形状、状态层、海拔和动效；App 提供平台动态颜色及用户偏好，M3 应用相应设计令牌。
- 种子色和动态色彩算法依照 Material Color Utilities 校验，规范版本与来源进入覆盖矩阵。
- 每个标准组件定义公开属性、状态、输入行为、无障碍语义、主题资源和适配范围。
- 全部标准组件按照锁定的 M3 Expressive 清单验收，覆盖矩阵逐项记录状态、证据和规范来源。
- 通用组件展厅与包保持同仓库演进，使用通用内容和可控主题输入展示组件状态。
- 包消费是 App → M3 的版本契约；开发期可使用本地包源，发布期使用明确的包版本及变更记录。
- App 的 Native AOT 与 GC 选择通过宿主验证，M3 自身提供 AOT、裁剪及公开 API 兼容证据。
- 跨仓库任务使用完整 GitHub Issue 链接与版本需求表达阻塞关系。
- 当前阶段由主代理按票据依赖图调度独立 worktree 子代理，结果统一合并到 `integration/m3-spec-1`；验收证据与未满足项分别记录，main 不在本批修改。

## Testing Decisions

用户确认的场景验收原则应用于 M3：通过完整的主题与组件使用场景检查外部行为，结合真实平台验证输入、布局和发布兼容。

主要测试入口为组件展厅或等价的通用宿主，使用可控主题、输入和窗口环境。独立算法测试覆盖色彩生成和重要边界，公开 API 与组件结果构成断言依据。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| M01 | 对照锁定规范与组件覆盖矩阵 | 令牌及全部标准组件的交付证据完整 |
| M02 | 相同种子色、主题和参数生成色彩方案 | 与参考算法的角色值一致 |
| M03 | 运行时切换明暗主题、动态色和字体尺度 | 所有相关组件更新，布局保持可读 |
| M04 | 组件处于按下、选中、聚焦、禁用及错误状态 | 外观、语义与交互契约一致 |
| M05 | 触摸、鼠标、键盘和读屏访问组件 | 输入行为、焦点和状态反馈正确 |
| M06 | 长文本、多语言、窄窗口与较宽窗口 | 内容和触达区域保持清楚布局 |
| M07 | 模板、属性及内容插槽扩展 | 扩展遵循公开契约并保持标准状态行为 |
| M08 | 动效与减少动效偏好变化 | 过渡反馈和用户偏好一致 |
| M09 | 展厅与引用包的独立宿主构建和运行 | 包契约、资源与组件可直接消费 |
| M10 | 宿主 AOT 发布、裁剪和冷启动 | 组件与主题资源在发布配置中工作 |
| M11 | App 消费明确包版本并升级 | 集成行为符合兼容范围和升级说明 |

## Out of Scope

本规格聚焦通用 Material 3 Expressive 设计系统。Pixiv 业务、账号会话、下载调度、搜索历史、中文业务文案、详情手势和重力换边由 App 规格负责。

Android 应用的运行时组合、签名和整包发布由 App 仓库组织；M3 提供被消费组件的兼容证据与通用宿主验证。

## Further Notes

实施先锁定规范基线、公开契约和覆盖矩阵，再建立主题令牌、基础组件及展厅；随后逐项完成全部标准组件、无障碍、跨平台和包发布验收。App 可按照稳定的已发布契约逐步集成。

共同决策参考 [两个独立仓库 ADR](adr/0002-two-independent-repositories.md) 与 [技术方向 ADR](adr/0001-avalonia-material3-expressive.md)。规范来源为 [Material 3 组件](https://m3.material.io/components)、[Material 3 Expressive](https://developer.android.com/develop/ui/compose/designsystems/material3) 与 [Material Color Utilities](https://github.com/material-foundation/material-color-utilities)。
